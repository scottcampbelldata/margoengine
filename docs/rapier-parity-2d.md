# Rapier 2D parity audit: page by page

Scott, 2026-11-24: "I want this physics engine to be as good or better than Rapier and have all the same features or more." That covers `@margoengine/physics2d`. This file audits it against Rapier's published JavaScript user guide for the 2D build (`@dimforge/rapier2d`, JS guide 0.21 at rapier.rs/docs/user_guides/javascript), one guide page at a time. Only published pages were read; no file under `node_modules/@dimforge` and no Rapier source. The pages are Getting started, Rigid-bodies, Colliders, Joints, Joint constraints, Soft-bodies, Controllers (character, vehicle, PID), Scene queries, Advanced collision-detection (events, the contact and intersection graphs, hooks, CCD), Debug-renderer, Serialization and Determinism. The guide has no separate pages for integration parameters, simulation structures or testbeds; the integration parameters are listed in the 3D audit's rows P-01 to P-33 of [rapier-parity.md](rapier-parity.md), which apply to 2D as well.

A row is DONE only when a named test exercises the capability. A row without one is MISSING: it is built, with its test, before it is called done. Statuses: DONE, MISSING (nothing built or no test), PARTIAL (part DONE, the rest named). Every row was set again from the code and its named test on 2026-11-26. The Owner column names the solver row of [physics-work-queue.md](physics-work-queue.md) that the open work of a PARTIAL or MISSING row belongs to (`DYN-02` for the 2D rigid body), or `unassigned` when no solver row covers it; a DONE row has `—`. Tests are in `packages/physics2d/tests` unless a path says otherwise. Rapier's names are the guide's own; Margo's are the 2D facade's (`Physics2D`, `Body2D`, `Collider2D`, `Joint2D`).

Found while auditing: the 2D facade had no way to lock rotation after creation, no `resetTorques`, no force at a point, and no setters for the collision-type, event and contact-force settings of a collider (all built and tested since, rows R2-11, R2-13, R2-16, C2-16 and C2-17), and the character controller's slope, autostep, snap and push options had no test (K2-02 to K2-07; a slope past the climb limit was slid up like a ramp, fixed). Built since on 2026-11-26: changing a collider's offset, shape or mass after creation (C2-08 to C2-10), friction and restitution combine rules (C2-12), a contact skin (C2-13) and the remaining integration parameters (D2-04). The trimesh flags (C2-03) since too. Still missing: a vehicle controller (K2-09). The 2D guide has a Soft-bodies page that covers 2D (ropes, grids, polygons, disks, polylines, trimeshes and volumetric bodies, the constraints solver and the FEM solver): none of it exists yet, and no solver row owns it.

## What beats Rapier already

Where Margo is more accurate than Rapier 2D, the measurement and how to reproduce it is a claim in `docs/whitepaper/claims.md`: branched trees of joints solved exactly (Baraff 1996 sparse elimination, `joint/tree.rs`) where Rapier's impulse joints are iterative, and the 20-row pyramid that drops less and sleeps sooner than Box2D v3's and Rapier 2D's (LIM-527). Any further measured win goes in the same file with its reproduction.
