# Site demos on the WebGL2 compatibility layer

Every live demo on margoengine.com and every model of the Khronos gallery, drawn once on native WebGPU and once on the
WebGL2 compatibility layer (`@margoengine/webgl2-compat`), in the same browser on the same GPU. A visitor whose browser
has no WebGPU gets the second picture: the demo page's gate ([examples/needs-webgpu.js](../examples/needs-webgpu.js))
downloads the layer only then, and a browser with WebGPU downloads none of it.

How it is measured: `npm run visual:compat` ([scripts/visual-compat.mjs](../scripts/visual-compat.mjs)) removes
`navigator.gpu` before a site page loads, so the page loads the layer exactly as a visitor's browser would. Each demo is
captured natively twice (its run-to-run noise) and on the layer once, at its desktop view (the gallery's model view),
as the still frame the visual check uses (prefers-reduced-motion). Per pixel, d is the largest RGB channel difference
(0 to 255). "Same pixels" is the roadmap's parity rule: at most 0.1% of pixels with d > 2 and a mean d of at most 0.25.
"Runs with differences" states the numbers, and "refused" quotes what the page shows: the part of the demo that needs
WebGPU refuses the layer with MargoError code `unsupported`. Frame work is the main-thread time of one animation
frame's callbacks (the layer translates and replays the frame's GL calls there), median of 60 frames; the interval is
the time between frames. Both are for the still frame, not a moving camera (`gameplay-sandbox` and `windy-meadow` stop
drawing under reduced motion, so theirs are for the running demo), and are measured by a step of their own,
`npm run visual:compat:budget` ([scripts/visual-compat-budget.mjs](../scripts/visual-compat-budget.mjs)), which holds
the GPU exclusively in chunks of 8 demos: measured beside other GPU work, a frame time counts that work too.

The check runs in `npm run check:merge` and fails when a demo's status changes, when a demo with differences gets
worse than its recorded numbers, when a demo recorded with an exact still frame ("exact" in the native column: its two
native captures equal pixel for pixel) no longer has one. Its budget step fails when a demo's median frame on the
layer costs more than the budget (50 ms by default; `--budget=<ms>` for an integrated GPU) and more than twice its
native frame, and when a demo draws too few frames to give a median on either path. `npm run visual:compat -- --write` records a new run's pixels here and in
[scripts/support/visual-compat-expected.json](../scripts/support/visual-compat-expected.json), and
`npm run visual:compat:budget -- --write` the frame column. Record either only with nothing else on the GPU.

## Accepted difference: per-sample reads of multisampled textures

Scott accepted, 2026-10-31.

WebGL2's shading language (GLSL ES 3.00) cannot read one sample of a multisampled texture. The layer resolves such a
texture with a blit before a shader samples it, so `textureLoad(t, p, i)` returns the same resolved value for every
`i`. Native WebGPU reads each sample: core's depth resolve (`resolveDepth` in packages/core/src/renderer.ts) and the post
stack's (`SceneTarget` in packages/shared/msaa.js) keep each pixel's nearest of the 4 samples, and fog, SSAO,
volumetrics, decals and TAA read that depth. The difference stays on
silhouette edges. Like for like, the same page at 1x MSAA (`?quality=light`, no multisampled textures), Edge 156 on
the RTX A6000, 2026-10-30:

| Demo | 4x MSAA (the table above): d > 2 | 1x MSAA: d > 2, max d |
| --- | --- | --- |
| `dof` | 0.66% | 0.000%, 1 |
| `gameplay-sandbox` | 1.16% | 0.006%, 98 (13 pixels with d > 2) |
| `night-citadel` | 0.20% | 0.000%, 2 |
| `voxel-ground` | 0.41% | 0.004%, 123 |
| `voxel-night` | 0.22% | 0.001%, 79 |
| `voxel-overview` | 1.24% | 0.009%, 125 |
| `voxel-shapes` | 0.23% | 0.003%, 153 |

At 1x MSAA all seven are within the parity rule. The voxel views read the resolved depth for their fog (before the
layer's fix of 2026-10-30 they also differed through Bloom, voxel night by 1.51% at 1x). Measured with a local build whose native depth
resolve keeps sample 0 (what the layer's blit keeps) in place of the nearest sample, voxel night differs on 0.001% of
pixels instead of 0.22%.
