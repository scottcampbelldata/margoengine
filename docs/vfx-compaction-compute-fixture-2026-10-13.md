# Private three-way real-VFX compute fixture

Static preparation was followed by the authorized native **headless correctness-only** run below. No package build, CPU/GPU speed benchmark or physical presentation test was run. `test-results/vfx-compaction-variants.mjs` uses the preserved source generator `scripts/support/vfx-workgroup-candidate.js`; its original prepared files are unchanged. It emits three separately hashed WGSL strings: original 256-thread simulation, ungrouped 64-thread width control, and grouped 64-thread compaction. The width control differs in one workgroup-size token; reversing that token reproduces the original shader exactly. Reversing the grouped helper/return edits reproduces the same simulation body, with all gravity/curl/respawn/lifetime/bounce/rotation expressions intact.

The distinct optimized grouped candidate removes only the lane-zero `atomicStore(groupCount,0)` and its preceding synchronization barrier from the legacy candidate. [WGSL variable initialization](https://www.w3.org/TR/WGSL/#var-decl) gives workgroup atomic storage the zero value of its underlying integer type. No invocation explicitly overwrites that initial counter; the first local atomic may therefore start from the specified zero without that reset/barrier. Two unconditional workgroup barriers remain: all local live tickets complete before lane zero obtains the global range, then the range is visible before live lanes write IDs. Every lane, including padded final-group lanes, reaches both barriers; early returns remain inside the simulation helper. Native headless compilation/uniformity validation passed for the tested fixture; native generated code was not inspected. The compiler may still emit workgroup initialization/synchronization; shader-source removal does not promise native instruction or timing savings.

## Small direct fixture and exact proof

`test-results/vfx-compaction-compute-browser.mjs` prepares `installVfxCompactionCompute` and `exerciseVfxCompactionCompute`, reusing the existing direct native VFX fixture pattern: the actual retained VFX constructor/device, actual `simulate` method for 224-byte header packing with a no-command encoder, direct compute dispatch and pooled native timestamps. It creates no second engine or renderer. Exact original shader identity must have matched during app boot. It requires the retained/current **one-state** VFX ABI (64B records, bindings 0/1/3/4/5) and rejects the old archived live ping-pong implementation. Current shader source SHA is `d42742af00b8d7f4d37a91b4c9b65e8071cd3c6e00f16f8a4fd6f6b6c70c1cd0`; extracted original WGSL SHA `72f1d762fab9e6e5c03794a0395597c8142e71a1d023ae3faf0dfffab60de8df`. This provenance is distinct from archived live simulation SHA `c1f4f391cb3702effe9c3799c295307a90459efaf49a348ff8e94c756df1d912` used by the blend test.

The installer changes only exact simulation-module bytes when making private effects. The caller passes `variants` from `test-results/vfx-compaction-compute-config.json`, installs before constructing actual VFX, then evaluates the exercise function. The correctness-only headless launcher serves immutable public-dist copies through Vite and exposes the actual constructor/device with a fake setup engine; it creates no render loop or window-canvas scene. Native Intel/nonfallback identity is verified before dispatch. A future performance/native-presentation caller must additionally obtain a user-awake/unlocked desktop and exclusive slot, preserve exact helpers/entry and record native input desktop/foreground evidence. Browser `visible`/`document.hasFocus()` alone cannot establish an awake interactive Windows desktop. This headless launch measured correctness only.

Quality phase defaults to capacities 1/63/64/65/257/1M and full/sparse/empty records. Every variant starts from identical 64B records, actual class-packed headers, sequence 123 and zero emission budget. Three direct dispatches per case also test fresh workgroup counter initialization across dispatches. Full cases have long live lifetimes; sparse/empty expiry has no respawn births. Staging reads occur outside timing. The fixture verifies every state word, the complete live ID set (bounds/no duplicates/no missing IDs), all five indirect words and both respawn words. It records actual alive-ID order separately and never canonicalizes that order to claim image equality. Private COPY_SRC-capable alive/respawn buffers enable proof without modifying production usage flags. Reports contain compact counts/comparison results rather than serializing hundreds of megabytes of particle arrays.

Respawn phase is separate: identical reset seed and sequence 123, limited budget `max(1,floor(capacity/3))`, repeated original A/A captures, then original/control/grouped comparisons. Baseline A/A state/ID-order/seed-selection variability is retained. A/B mismatch is reported, not asserted away or converted into an aggregate-count pass. Global respawn ticket order chooses IDs and sequence-based random seeds, so changing width/scheduling can alter particle state even with identical arithmetic. Equal baseline distributions cannot establish exact public behavior.

Timing is a further separate opt-in phase requiring an explicitly negotiated private timestamp-query device. It alternates original/control/grouped then grouped/control/original in one measured command buffer, after warm-up; seed/reset, compilation, buffer/query creation, resolves and readback are outside pass timestamps. It measures **direct compute only**, full-live constant header/time and no billboard consumption. Native ns are read with BigInt, not calibrated to page/CDP/physical presentation. No result from this phase can by itself establish whole-app FPS, draw synchronization cost, general respawn performance or exact HDR quality. Resource counts must remain unchanged during the measured dispatches.

For an eventual output claim, reuse the existing native HDR/depth fixture after exact state/set checks: compare original A/A and A/B actual atomic-order images, with mixed colors/alphas/overlap, native occlusion and every depth/HDR sample. Canonical ID rendering is a separately labeled diagnostic only. Changing alive order can change finite-precision source-alpha accumulation. The unchanged billboard and 64B ABI do not remove that risk. Generic exact-quality adoption may be infeasible; retain original production behavior unless actual state/respawn/order-sensitive HDR proof, CPU/GPU benefit and no-byte-growth gates all pass.

All private effects are registered for finally cleanup before `setup`, so partial setup failure still disposes allocated state. Owned staging buffers unmap/destroy in finally, validation scopes pop once, and the fixture leaves the shared device to its original owner. The installer exposes guarded restoration and reports later-hook conflicts. The caller restores hooks, retires app/device once, closes browser/server and verifies native owned-process state on success or error; native input state is additionally required for performance acceptance. Static tests passed 4/4, covering source reconstruction, partial-group full/sparse/empty proof, invalid ID/ABI rejection and partial setup/error-scope retirement; launcher guards extended that to 7/7 before GPU execution.
