# Draped terrain imagery

`@margoengine/terrain/imagery` exports `TerrainImagery`, `xyzImagery`, `wmtsImagery` and their fully typed settings. Attach a collection to an attached clipmap `Terrain` or `PlanetTerrain`. Its ordered layers compose straight alpha in linear light before terrain lighting. `add` returns a stable ID; `set` changes alpha, brightness, visibility or bounds; `move` changes bottom-to-top order; `remove` cancels requests and releases owned resources. GPU textures are borrowed through restoration factories and are never destroyed by imagery. Source credits are available through `credits` for application display.

Clipmaps use world XZ rectangles. Their full tile pyramid covers the terrain origin/size unless collection bounds override it. Planets use degrees, longitude about +Y, longitude zero on +X and east toward +Z. Layer rectangles are west/south/east/north. A GPU picture covers its rectangle, north at the top on a planet. Tiled layers retain global pyramid coordinates when clipped. Geographic and Web Mercator pyramids, north-origin XYZ rows, one or two root columns, and named WMTS matrix identifiers are supported. WMTS accepts REST templates or GetTile KVP, styles, MIME format and extra dimensions. Explicit matrix metadata is supplied by the caller; no capabilities parser is included.

Camera selection maintains nested windows with a coarse parent fallback and a bounded resident array per tiled layer. `update(center, level, signal)` can instead select a deterministic view: normalized XZ on clipmaps or normalized longitude/latitude with north at zero on planets. `automatic: false` disables camera selection. `ready` exposes the most recent load promise; HTTP, decoder and custom provider errors reject it and appear in `error`, without retries. Requests are canceled on replacement, removal, restoration and disposal. Custom loaders must honor their AbortSignal and return a tile-sized bitmap or straight RGBA sRGB bytes. Textures and pages from an obsolete device are never uploaded to its replacement.

Defaults: four maximum layers, 64 resident tiles per layer, four parallel requests, automatic camera selection, alpha 1, brightness 1 and visible. Tiled sources default to 256 px, levels 0..18 and Web Mercator. Limits are 1..8 layers subject to the device's sampled-texture capacity, 4..256 pages, 1..16 requests, tile sides 1..4096, and zoom 0..22. A 256 px 64-page layer uses 16 MiB of GPU cache; borrowed textures add no image copy. Rectangles crossing the antimeridian are represented by two layers. Filtering clamps to tile texel centers; cross-tile anisotropic filtering is not claimed. Camera selection uses altitude and nested windows rather than per-patch screen-error imagery refinement. High zooms can fall back directly to the pinned coarse image when the page budget fills.

The clipmap effect composes after an RVT reader when both are used. Its imagery is evaluated on the terrain surface, including slopes, without displaced overlay geometry. Planet terrain now accepts the same `TerrainLighting` interface in its optional planet entry. Neither core nor stage changes. Layer materials and other effects still share the device's texture/storage limits. Attach imagery after an RVT and before an effect that replaces the ground-color call.

Evidence: `packages/terrain/test/imagery.test.js` checks addressing, bounded residency, order, atomic style validation, borrowing, restoration, cancellation, stale results and observable failures. `imagery.browser.mjs` renders clipmap, RVT and planet surfaces on native WebGPU and the WebGL2 compatibility layer. The real CC0 Poly Haven Aerial Rocks 02 image, already recorded in THIRD-PARTY-NOTICES, must match exactly through GPU, XYZ and WMTS sources. It also proves alpha/brightness composition against a linear texture oracle, order changes, bounds and zero alpha. Analytic solid colors serve as mathematical composition fixtures, not demo assets. No speed claim is made.
