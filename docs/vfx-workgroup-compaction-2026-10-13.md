# Private VFX workgroup compaction preparation

The current production simulation uses 256-thread workgroups and performs one
global `indirect.instanceCount` atomic increment for each live particle. The
private candidate uses 64 threads, a workgroup-local live counter/ticket, and one
global reservation for each workgroup. At one million fully live particles this
reduces the maximum global reservations from 1,000,000 to 15,625. This is an
operation-count observation, not a GPU performance result. Three barriers and
one local atomic per live particle add work; hardware profiling is required.

Prepared files are `test-results/vfx-workgroup64-original.wgsl`,
`test-results/vfx-workgroup64-candidate.wgsl` and
`test-results/vfx-workgroup64-index-candidate.ts`, generated by
`scripts/support/vfx-workgroup-candidate.js`. No production source, emitted
package, browser or GPU was changed. No shader was compiled and no benchmark
was run. Only private source generation, exact reconstruction assertions and
string byte measurement were executed.

The simulation's original capacity check, failed respawn-budget return and final
dead-particle return now return false from a helper. They never return from the
entry point: every invocation, including padding lanes in the final partial
workgroup, reaches all three unconditional barriers. Lane zero initializes the
counter and publishes the shared base after the local tickets are collected.
After the final barrier, only live invocations write `alive[base+ticket]`.
Reversing only those helper/return/compaction edits reconstructs the original
simulation byte-exactly. Particle records remain 16 floats/64 bytes; bindings,
uniform header, indirect layout, capacity ceiling and public API remain intact.
The private host source changes only dispatch division from 256 to 64. Existing
256-thread device-limit validation is retained. Scratch is eight bytes of
workgroup memory; no GPU buffers or per-frame allocations are added.

The standalone simulation string grows 2,722 to 3,162 raw bytes (+440), and
1,130 to 1,263 gzip bytes (+133). These are **shader-string bytes only**; they
do not establish the package/consumer byte gate. A later write:false matched
build must measure the full optional package and actual consumer. There is no
demonstrated byte recovery, and existing comment-recovery candidates must not
be counted twice.

## Exact parity constraints

The current shader already has scheduling-dependent respawn behavior: global
`respawn.count` ticket order selects which expired particle IDs receive a
limited budget, and `respawn.sequence` ticket plus particle ID determines the
random seed. Changing workgroup width from 256 to 64, or adding synchronization,
can change these orders even though every simulation arithmetic expression is
preserved. Equal total births or similar distributions are insufficient to
prove exact particle-state parity during respawn.

Compaction order is also observable because the unchanged billboard pipeline
uses source-alpha/one-minus-source-alpha blending. Group reservations make each
workgroup's live records contiguous and can alter global and intra-group draw
order. Equal ID sets/counts do not establish equal HDR output. Canonical-ID
rendering is useful to isolate state/geometry, but cannot substitute for actual
indirect production-order images. Even identical RGB particles can accumulate
different finite-precision blend results when their alpha differs.

Generic bit-exact respawn/state and blended-image parity therefore cannot be
promised from this source transformation. It remains an unadopted investigation.

## Same-device quality and timing plan, pending slot grant

1. Compile original and candidate pipelines on one real device using identical
   explicit bindings and resource sizes. Capture compilation messages and
   validation scopes. Start with capacities 1, 63, 64, 65, 127, 129, 257 and
   1,000,000, including empty, sparse, fully live and partially final groups.
   Clone the same 64-byte initial records and complete 224-byte frame header;
   reset both indirect instance counts and respawn counters identically.
2. For deterministic no-respawn cases, compare every particle word, all five
   indirect words and live occupancy after each step. Check count against live
   records, all IDs below capacity, no duplicates and no missing live IDs.
   Exercise gravity, analytic curl, floor bounce, rotation, zero delta,
   heterogeneous lifetimes, particles expiring without budget and edge clipping.
   Direct state copies use private fixture COPY_SRC support on both alive and
   respawn buffers; this must not add production usage flags or timed transfers.
3. Run bounded respawn/burst cases separately: budget zero, one, partial and
   capacity, mixed initial life and repeated expiry. Record baseline A/A
   reproducibility before A/B comparison. Compare exact state, sequence values,
   selected IDs and errors. A scheduling-related mismatch remains a parity
   failure; do not reinterpret aggregate counts as an exact pass.
4. Restore the same captured native HDR and reversed-Z depth samples before
   each A/B draw. Compare every HDR channel and depth sample, nonfinite values,
   nonempty particle coverage and indirect count at matched DPR 1 and sample
   count 1. Include overlap, different colors/alphas, occluded geometry, clipping,
   rotated billboards and representative native camera views. Save both actual
   unordered indirect images and separately labeled canonical-ID images.
   Baseline A/A image variation must be recorded. Actual-order HDR/depth equality
   is required for an exact output claim.
5. After quality passes, measure same-device, same-command-buffer alternating
   pairs with compute and draw timestamps and paired span, separately from app
   callbacks. An ungrouped 64-thread control isolates the workgroup-width change
   from aggregation. Measure full-live, sparse and frequent-respawn cases; a
   full-live-only gain does not establish a general package improvement. Keep
   readbacks, counter resets, resource creation and shader compilation outside
   the timed ranges. Require zero steady GPU resource/query allocations.
6. If package parity, timing and bytes pass, test the actual whole native app at
   matched DPR/sample count and current quality. Preserve its existing measured
   33 Hz failure until a fresh native comparison proves improvement. The prior
   MSAA-only control cannot attribute the remaining cost to this atomic.

For every normal, rejected compilation, validation error and early-return path,
use try/finally to end owned passes, pop pushed error scopes, unmap staging
buffers, stop RAF and dispose owned effects/contexts. Validate once-only buffer
retirement and unchanged idempotent dispose, device-restore and unattached
`gpuState` error behavior. No worker, interval, device or browser may remain
after a failed fixture. Destruction belongs to its original owner; do not destroy
an already retired shared device a second time.

## Narrower fallback if the general candidate fails parity

Retain the current 256-thread workgroup and original simulation/respawn logic.
Consider aggregation only for workgroups proven fully live with no respawn;
retain the original per-particle global reservation for every other workgroup.
Do not infer this condition from emission budget zero or prior indirect count:
existing particles may expire. A private post-simulation all-live test plus an
initial no-expiry check can define the branch without a public flag, capability
or altered lifetime rules. This reduces the scheduling/feature scope but still
requires full state and actual-order blended-image checks: synchronization can
affect other workgroups' respawn tickets, and aggregation still changes ordering.
It is a proposal, not a prepared or measured production fallback. If exact
images/state remain infeasible, retain the current implementation and investigate
measured compute-versus-fragment costs instead of claiming a lossless fix.

Raw preparation/source hashes, exact reconstruction and shader-only sizes are
in `test-results/vfx-workgroup64-preparation.json`; executed preparation output
is preserved in `test-results/vfx-workgroup64-preparation-20261013.log`.

## Distinct optimized private preparation

The legacy three-barrier candidate above remains unchanged as evidence. A later three-way fixture adds original256, ungrouped64 and grouped64 comparison, with the grouped variant removing only the explicit zero-store/first barrier because WGSL specifies a zero initial workgroup atomic value. That distinct variant retains two unconditional barriers and costs +373 raw/+116 shader gzip bytes. Its subsequent native headless correctness run passed54 no-birth state/set/count cases; alive order changed and27 respawn cases showed both original A/A and A/B state/selected-ID variability. No image parity, GPU speed or package-size proof was run. See `docs/vfx-compaction-compute-fixture-2026-10-13.md` for exact hashes, guarded native hardware/cleanup evidence and lifecycle/ordering risks.
