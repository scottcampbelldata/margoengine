# Road design entries (batch 233)

## Intersections

`@margoengine/road/intersections` exports `intersections(roads, options)`, an async CPU builder. Each input uses the existing JunctionRoad shape: [x,z] points and width. Output geometry/UVs/area describe a single nonoverlapping driving surface. `curb` and `sidewalk` are separate geometry/UV/area layers (null when their width is zero); `footprint` owns [x,-z] polygon boundaries and holes.

Defaults: join round, cap round, miterLimit 4, turnRadius 2 m, arcTolerance 0.02 m, elevation 0, curbWidth 0.2 m, curbHeight 0.15 m, sidewalkWidth 1.8 m, uvMeters 1, signal none. Joins also accept miter and bevel; caps accept butt and square. Turn radii apply tangent circular fillets at reentrant boundary corners, including crossing corners. Convex joins retain the stroke setting. A radius that cannot fit the adjacent edges rejects instead of silently changing the design. Sidewalks surround the united footprint, so crossing surfaces contain no internal curbs.

Elevation accepts a constant or shared pure height(x,z) function. All layers use that same ground, with curb/sidewalk tops raised by curbHeight. Heights are sampled at triangulation vertices: planes are exact, nonlinear terrain is piecewise planar. Use denser authored approaches for finer ground detail. Face normals are calculated from the final float32 positions, preserving curb creases. This is at-grade geometry, without automatic bridge classification, traffic artwork or engineering certification.

Limits: 1..64 roads, 2..4096 points per road and 4096 total, no repeated neighbours; width 1e-6..1000 m; input/output coordinates +/-1e6 m; radius 0..1000 m; arc tolerance 1e-6..100 m; miter 1..100; curb/sidewalk widths 0..100 m; curb height 0.001..10 m; UV scale 1e-30..1e6. At most 4096 segments per curb-return arc and one million triangles per layer. Polygon snap rounding and renderer float32 set fidelity; collapsed final faces and overflowing UVs reject. The requested dimensions must remain representable near the chosen local origin.

Inputs snapshot before lazy polygon/triangulation loading. AbortSignal checks before/after loading and before return; synchronous CPU geometry cannot yield mid-operation. Output is caller-owned CPU data with no disposal requirement. Dispose meshes and engines that render it. Import/build allocate no GPU resources.

Evidence: `packages/road/test/intersections.test.js` compares analytic capsule, bend and crossing areas, tangent radius equations, holes, slope equations, normals, ownership, cancellation and rejection. `packages/road/test/browser-check.mjs` checks red road, blue curb and green sidewalk pixels on native WebGPU and real WebGL2 compatibility, exact reboot pixels and disposal. These are analytic correctness fixtures, not asset demos or timing measurements.

Research compared W3C SVG Working Group, Cameron McCormack and Dirk Schulze (editors), *SVG Strokes* (2015), https://www.w3.org/TR/svg-strokes/ (caps, circular joins and bounded miters); Eric Galin, Adrien Peytavie, Nicolas Marechal and Eric Guerin, *Procedural Generation of Roads* (2010), https://doi.org/10.1111/j.1467-8659.2009.01612.x (separate plan-view roads and terrain-aware surfaces); and ASAM, *OpenDRIVE 1.8.1: Junction reference line and elevation grid* (2024), https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/12_junctions/12_09_junction_reference_line.html (one shared junction height surface). Combined existing Margo stroke/union with tangent circular reentrant fillets and raised offset bands. Behaviour references: Cesium contributors, *CorridorGeometry*, https://cesium.com/learn/cesiumjs/ref-doc/CorridorGeometry.html and vis.gl contributors, *PathLayer*, https://deck.gl/docs/api-reference/layers/path-layer (2026 documentation). Tests cover their documented round/miter/bevel join, bounded miter and round cap semantics with independent closed-form oracles; Margo adds explicit crossing curb returns and sidewalk bands. No rival source read or copied files. The private CAD kernel's modeling documentation was inspected; its solid operations are unnecessary for these planar road footprints, which fit the existing engine polygon APIs.

## Lane paint
Optional road/lanes exports lanes(curve, layout, options), returning independent opaque line/arrow geometry, UVs, RGB and painted intervals. Layout widths are left-to-right looking forward (1..32 widths, 0.1..100 m). Boundary lines default solid outside, dashed inside, width 0.15 m, dash [3,6] m, phase 0, colour linear white. Supply exactly lane-count+1 line records to customise style (solid/dashed/none), width (0.001..10 m), dash components (0.001..10000 m), finite phase or colour (RGB 0..1). Default arrows empty, up to 4096; each selects a lane and distance, turn straight/left/right/straight-left/straight-right, length 4 m (0.1..100), width min(1.5, laneWidth*0.7), reverse false, colour white. Arrow width stays at most 90% of its lane and its whole footprint must fit the curve.
Options: step 0.5 m (0.001..1000), range [0,length], exclude empty (up to 4096 sorted or unsorted distance pairs), lift 0.01 m (0..10), elevation absent, signal none. Length 1e-6..1e6 m; 65536 quads per call, float32 positions within +/-1e6 m. Lines clip exactly at range and exclusions. Arrows crossing a range/exclusion edge are omitted whole. Dash phase uses route distance independently of clipping. For junctions suppress conflict-zone intervals on approach roads, and paint an authored connecting spline with the same lane layout; carry the approach length in phase for uninterrupted dashes. Splines can turn through arbitrary junction curves and closed routes. There is no automatic lane routing or traffic-symbol certification. Stylised arrows deform along the same curve/height as paint, including reverse travel. Shared height callbacks align lateral vertices to a sloped junction surface; absent callbacks use spline centre height. Chords approximate curved paint according to step, independent of dash lengths. Vertical/zero tangents and collapsed float32 triangles reject. Paint returns CPU data, no GPU resources; dispose rendered meshes/engines. Signal checks before/after synchronous building.
Research compared Richard L. Bishop, There is More than One Way to Frame a Curve (1975), https://doi.org/10.1080/00029890.1975.11993807 (stable moving frames), W3C SVG Working Group, SVG 2 Painting (2018/current text), https://www.w3.org/TR/SVG2/painting.html (distance-based dashes and offsets), and ASAM, OpenDRIVE with CityGML (2025), https://publications.pages.asam.net/standards/ASAM_OpenDRIVE_with_CityGML/index.html (lane-border markings in road coordinates). Combined Y-up tangent frames, arc-distance paint intervals and lane-relative offsets; no rival/companion code. The public deck.gl PathLayer curved-path behaviour is covered by analytic circular offsets, exact straight-road boundaries and spline/grade tests. No new asset demo or speed claim.
