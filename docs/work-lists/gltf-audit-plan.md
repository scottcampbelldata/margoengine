How to read this plan:

- CONFIRMED means a CPU script reproduced it on the built `dist` (the real loaders on a real `Engine` with a stand-in
  renderer or the recording WebGPU device of the package tests, a stand-in `fetch` and `createImageBitmap`, no GPU). The
  quoted line is the script's output. SUSPECTED means the code path was read end to end but not run. The scripts were
  kept outside the repository.
- Specification sections are from glTF 2.0 (Khronos, ISO/IEC 12113:2022). The section numbers and the quoted sentences
  of 3.2, 3.5.3, 3.6.1.2, 3.6.2.3, 3.6.2.4 and 3.7.2.1 were checked against the published text on 2026-11-11.
- Byte figures marked "measured" are gzip level 9 of the built `dist` file before and after the edit was applied to
  that file's text. They are deltas on the shipped text, not the official entry figures; measure each again with the
  package's size check when it is built.
- Every fix lands with the regression test named in its row, which must fail without the fix.
- Nothing here was already in `docs/known-bugs.md` or the bug sweep list. The depth limit (A4) and the "no renderable
  meshes" refusal (A3) are in `docs/limits.md` as limits; they are listed for the switching user only.
- WebGL2 layer: the code read has one path for both backends (the light `textured` entry and gltf-pro both draw
  through `engine.gpu`), so no layer difference was found by reading. B3 is about which texture a draw binds and needs
  its GPU half run on both.

## Suggested order

1. **B2** (accessor without a view in gltf-pro) and **B9** (version check): small, spec-backed, no ruling needed.
2. **B3** (the MASK draw binds the wrong texture), with the GPU test corrected to read what the draw binds.
3. **B4** (bitmap leaks and the plugin left behind), then **B13** in the same file.
4. **B1** once Scott rules on a zero scale in core.
5. **B5** and **B10** to **B12**: all make the light loader or `loadAuto` take or refuse the right files.
6. **B6** (scene) once it is known whether a package can read the active scene; **B7** and **B8**.
7. **S1** in both packages, then **S3** and **S4** (each proven by its count).
8. Table 3, starting with **A1**, **A5** and **A7**; then the suspected rows B14 to B17 as each is reproduced.
9. Read the files listed as not read, the draw path of `model.ts` first.

## Do not do

- Do not make a zero scale load by nudging it to a small number in the loaders: that is a stand-in, and it changes
  bounds and picking.
- Do not close B4 with a `FinalizationRegistry`: bitmaps must be closed when the load fails, not when memory is
  collected.
- Do not raise the light loader's 64 MiB budget for B5; send the file to gltf-pro.
- Do not apply S2 to the light loader (+7 B measured).
- Do not change the UV transform of `KHR_texture_transform` in either loader: the two agree and gltf-pro's is held by
  picture tests.
- Do not loosen `glbChunks` (`shared/glb.js`): its length, alignment and chunk-order checks match section 4.4.3.
- Do not add a download cache to the loaders for "two loads of one URL": each load owns its bytes, and no shared state
  was found between two loads.
