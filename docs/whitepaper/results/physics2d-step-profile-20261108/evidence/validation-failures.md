# Preserved harness and packaging failures

The original profiling attempt is `results.json` with `logs/run.log` and the original `templates/run.mjs`. It stopped before timed samples because exported Wasm i64 pins were formatted as signed hexadecimal. `BigInt.asUintN(64)` corrects representation, with directed assertions for signed and unsigned forms of all three pins. The same frozen physics modules, assertions, hashes and workloads then produced `results-v2.json`; no physics operation changed.

The first portable patch-validation smoke is retained in `logs/validate-bundle.log` and `bundle-validation-stages.json`. Git discovered the enclosing worktree from the nested owned archive, so `git apply` ignored paths outside the current repository prefix and returned success without applying them. The mandatory normalized source comparison detected the unchanged Cargo file and failed. No tracked file changed. The corrected validator sets the task-local `GIT_CEILING_DIRECTORIES` environment boundary, with no Git configuration or metadata writes, so the owned source-only archive is treated independently. A fresh `portable-validation-v2` tag then proved all nine generated diagnostic files identical to the frozen source and the actually applied patch. `portable-validation-v2.json` and `logs/validate-bundle-v2.log` contain that proof. Neither smoke ran a build or a new timing session.

The published `reproduce.mjs` never applies a patch or invokes Git: it validates the archive source hashes and uses the exact marker-checked generator. The review patch and the generator are independently proven equivalent by this smoke test.
