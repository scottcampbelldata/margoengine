# Public API changes, 2026-10-24

Codex's `work/changes` engine work (Studio integration, multi-view, voxel, lightmap, exporters) landed on `main` after a
review and rewrite. Names below that never reached `main` were only on that branch; apps that vendored a build of it
(Voxel Studio, Margo Mesh, MargoTile) update their imports from this list. No old names are kept.

## Core and the stage facade (multi-view, scenes, layers)

| Before | Now |
| --- | --- |
| `RenderView.mask` | `RenderView.layers` |
| `PassContext.view.mask` | `PassContext.view.layers` (the view record also has `count` and `clear`) |
| `PassContext.viewIndex` | `PassContext.view.index` |
| `PassContext.viewClear` | `PassContext.view.clear` |
| `engine.render({viewport, pixels, scissor, clear, mask, id})` | `engine.render({views: [{camera, viewport, pixels, scissor, clear, layers, id}]})` |
| `Mesh.layer` | `setRenderLayers(mesh, mask)` from `@margoengine/cameras/layers` (one layer concept) |
| `SceneView` | `RenderView` |
| `rectangleClear` | removed from the public API (core clears partial views itself) |
| `RenderView.target` colour must be the canvas format, 1 sample | any renderable colour format; a 4x MSAA view draws into core's own 4x textures, resolves colour into the target and writes the nearest depth sample into a 1x target depth |
| – | new `PassContext.view.target` (the view's target textures; absent for the canvas) |
| `Scene` (value export) | `Scene` is a type; create scenes with `engine.createScene(name)` |

## Cameras

**Behaviour change:** `getCameraLayers(camera)` now defaults to every layer (it was layer 0), so a mesh moved to
layer 2 with `setRenderLayers` stays visible until a camera or view is given a mask. Core draws layers per view; nothing
is hidden by toggling `mesh.visible` any more.

| Before | Now |
| --- | --- |
| `CameraLayers` plugin | `setCameraLayers(engine.camera, mask)`; core draws each view with its `layers`, else its camera's mask |
| `renderView(engine, options)`, `RenderViewOptions` | `engine.render({views: [{camera, layers}]})` |
| `SceneSwitch` | core scenes (`engine.createScene`, a view's `scene`) or layer masks |
| `getCameraLayers(camera)` default 1 (layer 0) | default every layer (`ALL_LAYERS`) |
| `CameraProjection` throws `Error` | throws `MargoError` (`state`, `attached`); new getter `fixedOrthographic` |

## Math

`Quaternion.normalize` now returns a unit quaternion for very large or very small inputs (it returned zeros or the
identity); ordinary inputs are unchanged.

New in `@margoengine/math/quat`: `rotationToQuaternion`, `axisAngleToQuaternion`, `conjugateQuaternion`,
`normalizeQuaternion`, `rotateByQuaternion`. Every package that converted matrices to quaternions uses them.

## Smaller entries (modularity)

No import path was renamed and no root lost an export: apps keep working as they are. Each new entry serves the same
functions as its root (`tests/entry-splits.test.js` checks identity), so code that needs only that part can import it
without loading the rest. The engine's own packages already switched.

| Entry | Exports (all also on the root) | Use it instead of the root in |
| --- | --- | --- |
| `@margoengine/decoders/texture` | `getSupportedTranscodeFormat`, `getBytesPerRow`, `createKTX2Texture`, `KTX2TextureOptions` | code that uploads already transcoded KTX2 textures |
| `@margoengine/gltf-pro/coordinates` | `textureCoordinates`, `TextureTransform` | material extensions |
| `@margoengine/materials/atlas` | `packAtlas`, `transformUVs`, `Atlas`, `AtlasOptions` | bakers and tools that only pack images |
| `@margoengine/animation/sampling` | `sampleTrack`, `sampleTrackInto`, `multiplyMatrices`, `Interpolation` | code that samples tracks itself |
| `@margoengine/loaders/common` | `LoaderError`, `fetchBytes`, `DEFAULT_MAX_BYTES`, `readZipDirectory`, `readZipEntry`, `crc32`, `computeVertexNormals`, `faceNormal` and the shared types | packages with their own format readers |
| `@margoengine/loaders/usd` | `parseUSDA`, `parseUSDZ`, `readUSDA` and the USD types | USD readers |
| `@margoengine/geometry/shapes` | curves, `Path`, `Shape`, `CurvePath`, triangulation, `extrudeGeometry`, `shapeGeometry` | text, SVG and outline code |
| `@margoengine/geometry/primitives` | `boxGeometry` ... `tubeGeometry` and the polyhedra | generators of simple solids |
| `@margoengine/geometry/utils` | `geometryData`, `toGeometry`, `pbrVertexStream`, `footprintRadius`, merging, normals, tangents, edges, wireframe | mesh tools |
| `@margoengine/controls/orbit` | `OrbitControls`, `MapControls`, `MOUSE`, `TOUCH`, `Controls` | apps that use orbit or map navigation only |
| `@margoengine/controls/transform` | `TransformControls`, `TransformControlsOptions`, `TransformSpace`, `TransformMode`, `HandleName` | editors with a transform gizmo |
| `@margoengine/controls/drag` | `DragControls`, `DragControlsOptions`, `DragObject` (loads bvh) | drag-to-move tools |
| `@margoengine/controls/profiles` | `MARGO`, `SOLIDWORKS`, `AUTOCAD`, `INVENTOR`, `FUSION`, `BLENDER`, `MAYA`, `ONSHAPE`, `RHINO`, `PROFILES` and the profile types | navigation presets |

Behaviour changes:

- gltf-pro loads `@margoengine/decoders` only when a file needs Draco or KTX2 decoding. It used to import the decoders
  root statically and lazily at once, which made bundlers fold the whole decoders module into startup (`@margoengine/gltf-pro`
  startup 525,254 B gzip before, 49,465 B after; `@margoengine/materials` 577,486 B before, 102,178 B after).
- Without Workers, `parseFBXInWorker` / `loadFBXInWorker` and `parseUSDInWorker` / `loadUSDZInWorker` load the
  main-thread parser with `import()` on first use; the worker entries no longer load it at startup. Results are the
  same model.
- `getBytesPerRow` with an unknown format now says which formats to use:
  `Unsupported KTX2 texture format <f>; use bc7-rgba-unorm, astc-4x4-unorm, etc2-rgba8unorm or rgba8unorm (with or without -srgb)`.

## Duplicate cleanup (one job, one place)

Every job now lives in one package (usually math or the owning package) and the others import it. Old names are not kept.

| Before | Now |
| --- | --- |
| `@margoengine/gizmo` (package: `Gizmo`, `TransformControls`, `buildGizmo`, `pickHandle`, `tessellate`) | removed; import them from `@margoengine/controls` (or `@margoengine/controls/transform`). `Gizmo` was another name for `TransformControls` |
| `@margoengine/usdz-export` (package: `exportUSDZ`) | removed; `exportUSDZ` from `@margoengine/exporters/usdz` |
| `exportUSDZ`, `USDZOptions` from `@margoengine/exporters` | `@margoengine/exporters/usdz` only (the root no longer carries the USDZ writer) |
| `Label`, `CSS3DObject`, `projectPoint` values from `@margoengine/html` | `@margoengine/labels` (html still exports the `Label` and `CSS3DObject` types its API uses) |
| `meshWorldMatrix` from `@margoengine/lines`, `@margoengine/points`, `@margoengine/text` | `@margoengine/math/mesh` |
| – | new `hexColor(text)` in `@margoengine/math/color` (and the math root): `[r, g, b, a]` sRGB 0..1 from `#rgb`, `#rrggbb` or `#rrggbbaa` (`#` optional), the one hex parser |
