# Scientific figure themes

Batch 178 job 6 adds the optional `@margoengine/sciviz/themes` entry. It has no import-time DOM, globals, settings or listeners. `createTheme(nameOrTheme, overrides)` validates and freezes a copied theme. Names are dark, light, print, print-mono and presentation. `applyTheme(figure, source, {signal})` resolves after owned chrome is ready and returns a disposable CSS-binding handle. The selected theme remains after handle disposal; disposal removes the binding/listeners and restores earlier CSS variable definitions. Figure disposal owns that cleanup too. Reapplying a theme replaces the preceding binding.

The Theme type accepts fontFamily, fontSize, titleSize, lineWidth, axisWidth, gridWidth, gridStyle, tickCount, tickSize, palette and scalarMap. Font sizes and widths use CSS pixels (1 pt = 4/3 CSS px). Default text is 12 px, 3D titles 13 px (2D titles remain 12 px when no override is given), data lines 2 px, field segments 1.5 px, frame 1.5 px, grid 1 px, five approximate major ticks and zero-length tick marks. Explicit AxesOptions.ticks takes precedence over the theme count. gridStyle is solid or none. tickSize adds inward major marks up to 64 px, using homogeneous projection to retain their screen length during resize, orbit and explicit rendering with a stopped loop. Theme count is 2..100; positive font/width tokens are at most 256 px. A family list cannot contain CSS declarations. Invalid options reject before mutation.

Shared typography, chrome, tick/grid geometry and frame weights apply regardless of the data layer: line, point, filled chart, surface, volume, mesh or an application-owned scientific layer. Default data-line widths update on existing native lines and field segments; explicitly authored widths remain. Live updates retain the resolved width. The native material and 2D vector style store are updated together. Palette and scalarMap are defaults for subsequently created native marks; explicit colours, maps, scalar domains, contours and classifications retain their scientific meaning. Applications creating optional/custom layers use themeLayerOptions(theme, seriesIndex, 'categorical'|'scalar') as defaults and then their explicit options. Scalar defaults omit a uniform color so a speed/intensity encoding cannot be accidentally masked. CSS font-size variables accept explicit px lengths; other numeric style variables are unitless. No unknown application-owned material is rewritten by reflection. Resolving a theme never normalizes data or silently substitutes another classification.

Print uses white paper, dark text/frame, restrained Tol muted/dark inks, Arial/Helvetica, 11 px text, 12 px titles, 1 pt lines, 0.5 pt frame, 0.25 pt grid and 3 px inward ticks. New scalar layers default to cividis. Print-mono supplies a grayscale categorical alternative and gray scalar defaults with no grid. Presentation increases text and stroke weights. Print palettes are device-independent sRGB choices, not a guarantee for every printer, paper, ink or CMYK profile. Category labels and shape/line encodings remain necessary when categories must survive grayscale reproduction. Math labels retain their explicitly supplied outline font and size. PDF text uses the caller's PDFOptions.font/fontForText; applications must supply fonts matching their chosen CSS family when identical outlines are required.

## CSS and portable exports

The binding writes --margo-font-family, --margo-font-size, --margo-title-size, --margo-background, --margo-axis, --margo-grid, --margo-text, --margo-line-width, --margo-axis-width, --margo-grid-width, --margo-tick-count, --margo-tick-size and --margo-grid-style on this figure's canvas and owned publication HTML roots. It does not write to the document, body, shared parent or a neighbour figure. HTML typography consumes the font variables. After editing canvas variables, call handle.refresh() to validate and synchronize native GPU geometry, controller SVG and exports. A themechange event from setTheme updates the binding, including high contrast. New publication roots bind once; removed roots release their saved style references.

SVG reads the same resolved fonts and native line/frame/tick/grid dimensions. PNG/WebP/video/image-sequence paths capture the same native geometry and computed HTML; PDF consumes that SVG. The portable spec saves complete resolved theme tokens. The controller's layout cache includes theme state, preventing stale on-screen axes after a style-only change. Accessibility UI owns a transparent, zero-margin/padding/border root so a page's section styling cannot paint a large box over data. This does not affect publication dimensions or include the accessibility controls in exports.

## Journal dimensions

journalPreset('nature'|'ieee', columns=1, options) returns immutable widthMM, heightMM, theme, css, raster and pdf options. Final Nature columns are 89/183 mm; IEEE columns are 88.9/182 mm. Nature uses 6.5 pt ordinary and 7 pt title text; IEEE uses 9.5/10 pt. Height defaults to width*0.67 and raster density to 300 dpi. Supply heightMM/dpi explicitly when the journal/article type needs another size or line-art density. css supplies physical CSS lengths, raster supplies an mm size and dpi for exportImage, and pdf supplies widthMM for exportPDF/svgToPDF. Screen millimetres follow 96 CSS px/in and do not promise a ruler-calibrated monitor. These presets cover final-column dimensions and typography, not complete publisher submission compliance: Nature requests editable text, while Margo's PDF font path uses outlines.

## Evidence and reproduction

Use existing real-data examples with ?theme=print or ?theme=print-mono. The shared example creator applies selected defaults before creating marks, and the explicit example accessibility integration binds subsequent styles. GHCN chart/secondary axes, the LIGO formula figure, scalar surfaces/volumes, native material widths, CSS refresh, author overrides, live updates and portable theme restore are covered on both WebGPU and WebGL2. The dedicated browser probe checks 3 px ticks before/after resize and a 3D camera change, 89 mm PNG dimensions and PDF MediaBox width. Run packages/sciviz/tests/themes-browser.mjs through the shared GPU lock after a package build. Unit tests cover immutability, token validation, exact mm/in conversion, scoped CSS variables, stable self-assignment, theme events, deleted-label release and owner cleanup. The machine-readable ledger is docs/whitepaper/results/batch178-themes.json. No speed claim or timing assertion is made.

## Clean-room basis

Compared these primary sources before implementation, without reading companion or rival source:

- Nicolas P. Rougier, Michael Droettboom and Philip E. Bourne, Ten Simple Rules for Better Figures (2014), https://doi.org/10.1371/journal.pcbi.1003833 . Medium-specific typography, strokes and contrast motivate separate print/presentation defaults.
- Nature editors, Final submission (accessed 2026-11-10), https://www.nature.com/nature/for-authors/final-submission . Final 89/183 mm columns, 5..7 pt sans-serif text and 0.25..1 pt lines; initial-submission 90/180 mm guidance is a different stage.
- IEEE Author Center editors, Resolution and Size and File Formatting (accessed 2026-11-10), https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-graphics-for-your-article/resolution-and-size/ and https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-graphics-for-your-article/file-formatting/ . 88.9/182 mm columns, 9..10 pt lettering and vector/raster-resolution guidance.
- Cynthia A. Brewer, Geoffrey W. Hatchard and Mark A. Harrower, ColorBrewer in print: A catalog of color schemes for maps (2003), https://doi.org/10.1559/152304003100010929 ; author-institution account https://pure.psu.edu/en/publications/colorbrewer-in-print-a-catalog-of-color-schemes-for-maps/ .
