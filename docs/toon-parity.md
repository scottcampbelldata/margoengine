## Pixel hulls

Import `Toon` and `ModelOutlines` from `@margoengine/toon/screen-outline` (also `margoengine/toon/screen-outline`). Their options are the existing constructors' options, with outline widths in drawing-buffer pixels: default 3, finite range 0 to 1024, zero hides. Core Toon options remain fixed at construction; ModelOutlines retains live outline/color, per-material styles, smooth, vertexColors and model filtering. Do not attach the world and pixel variants of one class simultaneously: they share the existing plugin name. ModelOutlines can coexist with core Toon.

The optional entry subclasses the existing renderers; only the selected entry contains homogeneous pixel projection. Transform the inverse-transpose normal by the view-projection, differentiate XY/W, normalize in viewport pixels, convert the requested pixel displacement to clip XY and preserve Z/W. This handles perspective, orthographic, rectangular viewports and resize without a camera-distance approximation. A zero projected normal or a vertex behind the eye gets no displacement. Existing depth testing, instancing, mirrored winding, smooth/deformed normals, material styles and vertex paint remain in the owning hull renderer. Core/stage sources do not change.

Drawing-buffer pixels are physical render-target pixels, not CSS pixels. At render scale 0.5 a width of 3 is 6 CSS pixels on a 1x display. Inverted hulls follow tessellated vertex normals; sharp corners and concavities retain the usual hull behaviour rather than becoming image dilation. This matches the documented screenspace width behaviour of drei Outlines for mesh, skinnedMesh and instancedMesh; no rival source or packages were used.

`screen-outline.test.js` records per-view uniforms and retained earlier-view values, disposal, static attach identity, smoothing/instancing/paint and live material widths. `screen-outline.browser.mjs` draws native WebGPU and full WebGL2 compatibility, two camera distances, perspective/orthographic and core/material spheres: 5 requested pixels measure 4 to 5 after rasterization. It also draws the real animated Fox at two poses. Fox is the existing Khronos standard test asset, model PixelMannen (CC0), rig/animation tomkranis and glTF conversion @AsoboStudio/@scurest (CC BY 4.0); its source/licence is already in THIRD-PARTY-NOTICES.md. Spheres are original mathematical test fixtures, not a new art demo. The existing model/hatching pixel suites also pass on both backends. No speed measurement or cross-vendor claim.

Reproduce after building packages: run `node --test --test-timeout=60000 packages/toon/test/*.test.js`, then `node scripts/gpu-lock.mjs run --owner=toon-parity --wait-max=60 --max=3 -- npm run test:gpu --workspace @margoengine/toon`. Repeat the GPU command with environment `MARGO_COMPAT=1`. These are correctness checks only.

## Model and material hatching

Job 3 adds ModelHatching.attach(model, options) from @margoengine/toon/hatch-models, also margoengine/toon/hatch-models. The borrowed object is a loaded PBRModel or a materials createMesh/createInstancedMesh mesh. Options, setters and set(options) are shared with core Hatching: hatch/halftone, spacing 8 (2..64 px), width 1.5 (0.5..spacing px), layers 3 (integer 1..4), angle 45 degrees (finite), ink black (linear RGB 0..1). The class has disposed, dispose and Symbol.dispose. The optional gltf-pro peer is required only for this entry; no import-time engine or adapter is created.

The model's original material records are temporarily borrowed during each beauty/transparent/capture draw and restored in finally. Prototype-backed copies retain live material getters, textures, native shading, alpha, variants and deformation without editing vertices or sharing caller GPU ownership. Original shader/pbr/lit/binding callbacks run with their own receiver. Ink mixes in linear light before tone mapping, sRGB and output/fog hooks; basic and matcap early encoder inputs receive the same mix. Normal/depth/distance data visualization materials and custom shaders without the standard display hook are outside this colour-material contract. Shape is screen-fixed: motion slides the surface behind the strokes. Tone follows the primary sun normal dot light, as core Hatching; local lights/shadows still shade the paper but do not change ink coverage. No UV/TAM parametrization or temporal stroke coherence is claimed.

The gltf-pro material-draw API permits one adapter per source model, so dispose an existing layer adapter before attaching hatching. This is the existing explicit ownership contract, not an implicit combination with MToon. Model disposal removes hatching; caller materials/textures stay live. New/restored devices allocate uniforms lazily, and per-view writes preserve earlier view values. Buffers are retired on device loss or disposal. Existing full compatibility tier is supported; the small preview refuses with a coded unsupported error.

Correctness exposed a gltf-pro bug that blocked this job: PBRDrawRun deferred material bindings until after call.draw returned, so an adapter's temporary records were already restored. The owning draw dispatch now flushes pending run batches inside each adapter call.draw, before a layer changes or returns. A regression in packages/gltf-pro/tests/material-draw-run.test.js fails on the parent: body bindings are undefined instead of body before the adapter returns; the fixed run observes body then outline synchronously. Normal draws without adapters retain existing batching. An adapter introduces a draw boundary per explicit layer because deferred commands must not observe another layer's records; no work is removed and no speed result is claimed.

Proof: hatch-models.test.js covers real loaded-model and materials records, live edits, atomic option validation, exact restoration, model-first disposal and compiler failure cleanup. The browser compares independent interior stripe/dot distance tests against material pixels (paper unchanged to 1 channel value), checks basic early returns, and compares animated Fox images before/after/disposal at two poses. Fox's model is PixelMannen (2014), CC0; rigging/animation tomkranis (2014) and glTF conversion @AsoboStudio/@scurest (2017), CC BY 4.0. Exact existing source and licence: examples/assets/khronos/README.md and THIRD-PARTY-NOTICES.md. No asset was copied from a rival repository.

Run the same toon CPU/GPU commands above; test:gpu now includes hatch-models.browser.mjs. The gltf-pro regression, changed package's GPU suites and dependent CPU suites run for the batching fix. Speed-phase timing remains deferred.
