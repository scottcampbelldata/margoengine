# Large time series, batch 175 job 4

The optional `@margoengine/sciviz/series` entry combines HTTP byte ranges, format-aware progressive tables, original binary64 observations, pixel-column sampling and the existing `@margoengine/compute/fft` transforms. Nothing is added to core or stage. Generated `margoengine/sciviz/series` and `@margoengine/viz/sciviz/series` aliases expose the same API.

## Loading and ownership

`openSeriesSource` discovers length with a two-byte Range probe, checks every 206 Content-Range and actual body length, rejects content coding and pins a strong ETag or Last-Modified when supplied. Headers support signed URLs and authenticated stores. Servers must expose Range response headers to cross-origin browser clients. An unversioned source must be immutable by application contract. A two-byte probe also avoids servers that mishandle a zero inclusive range endpoint. No whole-response fallback hides unsupported Range service.

`readSeries` is an async iterator over `SeriesChunk` with its table, original row offset, cumulative bytes requested and total file bytes. Repeated metadata reads count in requested bytes, so the counter can exceed file length. CSV records, Arrow record batches and Parquet row groups are yielded before fetching later observations. CSV preserves UTF-8 across byte boundaries, quoted newlines, escaped quotes, CRLF and final unterminated lines; provide CSV types for a stable schema across independently inferred blocks. Arrow file/stream framing preserves shared dictionary state and compression. Parquet first fetches its footer, then only projected column chunks. The existing table readers share these decoder paths; their whole-file APIs still materialize one table. Flat scalar formats and codec limits remain those of `/table`.

Default network chunks are 1 MiB, with a 512 MiB encoded/decoded block bound and 100 million row limit. Override explicit reader limits for larger blocks/row counts. The file size itself is not capped by the block bound. Arrow dictionaries and metadata remain resident, as required by the format. A CSV record itself must fit the block limit. Early iterator return issues no further reads; AbortSignal reaches fetch, block decoders and progressive drawing.

`TimeSeries` owns separate binary64 x/y blocks and copies only the newly appended block. Times must be finite and nondecreasing, including across blocks; NaN y marks gaps. Up to uint32 row IDs are supported. Exact original selection requires retaining all loaded observations: this API does not claim constant total browser memory. Reader-only clients may discard yielded blocks. There is no coarse query pretending that unrequested rows have been selected.

## Display and exact selection

`downsampleSeries` returns original indices. Default M4 retains each display column's first, last, minimum and maximum in time order, with one original neighbour on either side of the viewport and explicit gaps. Neighbours occupy their own projected columns so they cannot replace a visible column's entry point. Multiplying by the precomputed pixel scale avoids a divide-then-multiply rounding error at integer boundaries. Min-max retains per-column extrema and trace endpoints. LTTB implements Steinarsson's equal-count three-bucket triangle selection; by default it additionally unions per-pixel extrema, while `preserveExtremes:false` gives the original thresholded algorithm. LTTB is a visual heuristic, not a pixel-equivalence claim. Tiny and huge finite y values are normalized before LTTB triangle areas.

M4's exactness is the paper's aliased pixel-column line model. The independent test quantizes horizontal coordinates to integer columns and checks every rasterized pixel, including dense, sparse and viewport-entry cases. It does not promise bit-identical fractional antialiasing, thick joins, caps or subpixel blending compared with drawing every original segment. All methods preserve original values and sample identity, rather than averaging them. Gaps may require more than four times the display width in output. A monotonic transformX must be valid on the displayed interval.

`bindSeries` draws native Figure lines, splits NaN gaps, resamples after wheel/pointer completion and ResizeObserver changes, and supports explicit `refresh()` after programmatic limits. Its progressive `load()` awaits each completed draw before sending `progress`. It listens to Figure rectangle/lasso selection and emits its own `selection` event with exact original row IDs; `selected` and `select(region)` use original binary64 samples, not sampled line vertex IDs. Figure's ordinary native line selection remains its displayed-vertex selection. Applications sharing scientific row selection use the binding's original IDs. Completed original blocks remain available if a progressive load is cancelled; disposal removes traces and event listeners. Automatic redraw errors remain inspectable through `error` and the error event.

## Spectral views

`seriesSpectrum` transforms original finite, uniformly sampled values using `/compute/fft`, with periodic Hann window and mean removal by default, or a rectangular window. It returns physical binary64 complex coefficients and one-sided PSD in value squared per Hz, including correct DC/Nyquist handling. Values are normalized before f32 GPU upload and rescaled after readback, preventing LIGO strain power from being flushed to zero by GPU f32 arithmetic. Frequencies are never inferred from irregular times: callers supply a positive sample rate and choose a contiguous uniformly sampled interval.

`seriesSpectrogram` uses complete windows (default 256, half-window hop), one window of GPU staging, and a 256 MiB default output limit. Times are window centres, no zero padding is invented, and power is frequency-major for a native heatmap. `addSpectrumView` plots physical PSD; use a logarithmic Figure y scale for very small values. `addSpectrogramView` plots dB PSD with half-cell edge bounds. These are unfiltered signal views, not a gravitational-wave detection or whitening pipeline.

## Evidence and data

`examples/sciviz-series.html` progressively loads four seconds of actual H1 GW150914 strain through any of the three formats, then draws the original-data FFT and STFT. The raw GWOSC gzip SHA-256, sample interval, time origin, derived hashes and PyArrow 21.0.0 writer settings are pinned in `packages/sciviz/tests/fixtures/series/source.json`. Data: LIGO Scientific Collaboration and Virgo Collaboration, GWOSC, CC BY 4.0. No samples are fabricated or repeated. Original strain values are unchanged binary64 observations, not whitened/filtered.

The CPU suite compares all existing owner-writer Arrow/Parquet scalar fixtures (compression, nulls, units, dictionaries), tests every CSV chunk size through UTF-8/quotes, validates HTTP failure/cancellation, checks real format equivalence, independent M4 raster pixels and exact original selection, and compares FFT/PSD analytic tones at odd/even lengths. The browser suite verifies progressive draws, actual Figure selection after zoom, both binary formats, tiny-signal FFT/PSD, STFT, three nonuniform rendered views, cancellation and mobile resize. Both WebGPU and WebGL2 run; WebGL2 reports GPU scatter dispatches and zero CPU compute dispatches.

No wall-clock benchmark, paired timing run or speed assertion is claimed. Deterministic evidence: the real fixture has 16384 original rows; a 320-column M4 display emits at most 1282 rows while original selection remains complete. A future speed-phase run must measure larger remote recordings and throughput on a quiet machine.

## Research comparison and clean-room sources

- Uwe Jugel, Zbigniew Jerzak, Gregor Hackenbroich and Volker Markl (2014), *M4: A Visualization-Oriented Time Series Data Aggregation*, https://www.vldb.org/pvldb/vol7/p797-jugel.pdf. First/last plus extrema preserve line entry/exit, unlike min-max alone. Chosen as the default exact column model.
- Sveinn Steinarsson (2013), *Downsampling Time Series for Visual Representation*, University of Iceland, https://skemman.is/bitstream/1946/15343/3/SS_MSthesis.pdf. Equal-count LTTB and endpoint retention; kept as an explicitly heuristic alternative.
- Jeroen Van Der Donckt, Jonas Van Der Donckt, Michael Rademaker and Sofie Van Hoecke (2023), *MinMaxLTTB: Leveraging MinMax-Preselection to Scale LTTB*, https://arxiv.org/abs/2305.00332. Motivates keeping min-max as a separately useful reduction. We do not label a full-data LTTB pass as MinMaxLTTB or claim its measured acceleration.
- Apache Arrow contributors (2026), *Arrow Columnar Format*, https://arrow.apache.org/docs/format/Columnar.html; Apache Parquet contributors (2026), *File Format*, https://parquet.apache.org/docs/file-format/. Format-native batches/groups provide bounded progressive decode; arbitrary byte slicing alone does not.
- Roy Fielding, Mark Nottingham and Julian Reschke, editors (2022), *HTTP Semantics*, RFC 9110, https://www.rfc-editor.org/rfc/rfc9110.html. Inclusive ranges, If-Range and response validation. Yakov Shafranovich (2005), *Common Format and MIME Type for CSV Files*, RFC 4180, https://www.rfc-editor.org/rfc/rfc4180.html. Record boundaries must respect quotes.
- Peter D. Welch (1967), *The Use of Fast Fourier Transform for the Estimation of Power Spectra: A Method Based on Time Averaging Over Short, Modified Periodograms*, https://doi.org/10.1109/TAU.1967.1161901. Window energy normalization and modified periodograms; the spectrogram retains individual windows instead of averaging them.
- Naga K. Govindaraju, Brandon Lloyd, Yuri Dotsenko, Burton Smith and John Manferdelli (2008), *High Performance Discrete Fourier Transforms on Graphics Processors*, https://doi.org/10.1109/SC.2008.5213922. Existing compute FFT implementation reused, not rebuilt.

No rival, paper-companion or third-party implementation source was read, adapted or copied. The formats were written by PyArrow solely as standard-data reference fixtures. The requested rival behaviour is progressive remote tables plus min-max/M4/LTTB line reduction, exact original selection and FFT/STFT views, not an assertion of parity with unrelated chart features. Pixel and numerical limits above are explicit.

## Entry size

The new optional entry grows from absent (0 B) to 13801 B min+gzip, with a 14169 B ceiling. The bytes keep progressive format decoders, scientific row ownership and spectral lifecycle coherent; splitting would make applications manually assemble the same feature and could duplicate reader state. Existing /table is 12655 B after sharing the progressive decoder path. Core plus stage remains 24209 B before and after.
