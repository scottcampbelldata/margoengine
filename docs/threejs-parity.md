# three.js r186 parity matrix

What Margo Engine covers compared with three.js r186 and its common add-ons (`three/addons`), one row per feature group. It is for roadmap planning and for a public comparison page. COVERED and PARTIAL rows name the Margo package; "Shows it" links a page that runs the feature, where one is published. An empty cell means no page shows it yet, not that the feature is unchecked.

## Summary

190 three.js features in 19 areas (recounted from the rows 2026-10-31; 51 of the COVERED rows are marked †):

| Status | Count | Meaning |
| --- | --- | --- |
| COVERED | 156 | A Margo package implements the feature in a form a three.js user would accept as equivalent (limits noted). |
| PARTIAL | 4 | Some of it exists, but a common use case is missing. The notes say what. |
| MISSING | 17 | Worth having and not written yet. Listed below with what to do. |
| NOT PLANNED | 13 | Out of scope by decision. The note says why and what to use instead. |

The earlier version of this table had 161 rows and hid several gaps inside one coarse row or inside a COVERED row's notes. Those gaps now have rows of their own, which is why the MISSING count went up while no feature was lost.

Margo is strong where three.js relies on third-party libraries or examples: cascaded PCSS shadows, clustered lighting, TAA, Gaussian splats, BVH queries, physics, navigation, terrain, water and sky. Core has one directional light; everything else is an optional package. WebGL2 runs on `@margoengine/webgl2-compat`, still in development ([roadmap](webgl2-compat-roadmap.md)).

Legend. A **†** marks rows where the evidence is the exported symbols, the package README and a non-trivial amount of source code, not a line-by-line read. See [How this was checked](#how-this-was-checked). Rows that work only on WebGPU say "WebGPU only" in their notes.

## Margo extras

These are not in three.js core or its official add-ons. Many have third-party three.js equivalents (noted), which matters for an honest comparison page.

- **Rendering:** cascaded PCSS shadows with a static-caster cache (shadows); clustered forward lighting for up to 1,024 lights (clustered); TAA with motion vectors (taa); Gaussian splats with GPU covariance projection, radix sort and spherical harmonics up to degree 3 (splats; cf. third-party splat viewers); geometry-clipmap terrain with triplanar layers (terrain); GPU particles up to 1,000,000 with obstacles, sorting and sprites (vfx; creative `GPUParticles` is a preset of it); a 100k-blade grass field and a planet renderer (creative); physical day sky plus a stylized night with stars and a phased moon (sky; scenery `SkyMoon` is a preset of it); scene transitions (transitions); GPU scatter with distance LOD (scatter); GPU-driven frustum and Hi-Z occlusion culling with order-preserving compaction and indirect draws for static assemblies (culling); octahedral imposters (lod); vertex animation texture crowds (animation); device-loss recovery that rebuilds every plugin (`Engine.rebootDevice`).
- **Simulation and gameplay:** Rapier physics with a character controller (physics; cf. cannon-es or Rapier bindings); a dependency-free navmesh with A*, funnel paths, ORCA avoidance and navmesh generation from triangles (navmesh, navmesh/build; cf. three-pathfinding); sparse-set ECS (ecs); hierarchical state machine (fsm); snapshot interpolation for networking (net); a multiplayer voxel server, client and bot load test (voxel-net); semantic input with gamepad and haptics (input); tweening (tween); damped camera follow and shake (cinematic); animator blend trees and foot IK (animator).
- **Voxels:** block worlds with meshing, light, streaming, queries and physics colliders (voxel); MagicaVoxel `.vox` read and write (voxel/vox); voxel editing (voxel-edit); a progressive voxel path tracer with a denoiser and MagicaVoxel's look (voxel-pathtracer).
- **Content generation:** procedural cabins, trees, rocks, humanoids, marching cubes, noise and L-systems (procedural); 3D and 2D overlapping wave function collapse (wfc); spline roads (road); arc-length splines (splines).
- **Engineering and BIM:** IFC through `web-ifc` (ifc).
- **Tooling and integration:** React bindings (react; cf. react-three-fiber); triangle BVH with a worker build (bvh; cf. three-mesh-bvh); SDF text from any browser font (text; cf. troika-three-text); entity inspector (inspector); progressive glTF streaming with HTTP range requests (gltf-pro/progressive; cf. needle-tools progressive loaders); Blender `.margo` offline asset pipeline (blender); Rust/Wasm transform and culling kernel (kernel); CAD camera controls and `fitToBoundingBox` in core.

Positioning caveats for a public page:

- fbx and usdz used to run three.js code at runtime (`FBXLoader` and `GLTFExporter`; the USDA and USDC parsers). Both now have native parsers; three.js is only a test-time reference.
- Several capabilities exist twice. html and labels both export `CSS3DObject`. gizmo and usdz-export are pure re-exports. Two toon paths and two navigation packages remain. The particle, bloom and sky duplicates were merged (2026-10-14): vfx is the one particle system (creative `GPUParticles` is a preset over it), post `Bloom` the one bloom (creative `PostProcessing` lost its bloom), and sky the one sky (scenery `SkyMoon` is a preset; `SkyMoonPass`, `NightAtmosphere` and creative's `atmosphere.sky` backdrop were removed). The merge shrank the five packages' root entries; Night Citadel and Afterlight load a few kB more gzip because they now use the fuller single sky and particle implementations (measured locally at the time; that measurement was not committed).
- Many COVERED rows outside core are written for WebGPU. Against three.js's WebGL renderer, Margo's WebGL2 reach is the compatibility layer (milestones M0 to M8 done), which runs them on WebGL2 except the voxel path tracer and XR.

## How this was checked

- **Reading only.** The rows come from reading source code: exports, package `src/`, package READMEs. A row is not a statement that a feature works at runtime; the "Shows it" link and the package's GPU tests are the runtime evidence.
- **Re-audit, 2026-10-31.** Every example in the three.js r186 example list (names and categories only, never its source) was mapped to a Margo package from `packages/*/src` exports and `package.json` entries, and each feature with no match became a row here. The earlier row-by-row audits are in the git history of this file.
- **Rows marked †.** The named exports exist, the source is non-trivial, the README describes the behaviour and keyword searches agree. The code itself was not audited line by line.
- **The three.js side.** The feature list comes from knowledge of three.js r186, its documentation (<https://threejs.org/docs/>) and `three/addons`.
- **Re-checking.** `npm run check:parity` (part of verify) recounts the rows, fails if the Summary, the "Recounted" line or three-parity-matrix.md disagrees, and checks that every package, repository path and "Shows it" page named here exists. When a gap is closed, update its row and the counts. Update the [Not yet](from-threejs.md#not-yet) table when that page names the same gap.
