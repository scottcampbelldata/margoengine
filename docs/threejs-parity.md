# three.js r186 parity matrix

What Margo Engine covers compared with three.js r186 and its common add-ons (`three/addons`). It is meant for roadmap planning and as the source for a public comparison page. Every COVERED or PARTIAL claim names the Margo package, the export, and the file where the code lives.

## Summary

161 three.js features in 19 areas (recounted from the rows 2026-10-24, after the parity-closing work; 51 of the COVERED rows are marked †):

| Status | Count | Meaning |
| --- | --- | --- |
| COVERED | 153 | A Margo package implements the feature in a form a three.js user would accept as equivalent (limits noted). |
| PARTIAL | 4 | Some of it exists, but a common use case is missing. The notes say what. |
| MISSING | 4 | No implementation was found in any package's `src/`. |

Overall: Margo is strong where three.js relies on third-party libraries or examples. That includes cascaded PCSS shadows, clustered lighting, TAA, Gaussian splats, BVH queries, physics, navigation, terrain, water and sky. The day-one basics the first version of this matrix found missing (textures and materials on meshes you build, glTF extensions and compression, an orthographic camera, picking loaded models, image-based lighting outside React, combinable effects, FXAA, a math library) now exist as optional packages. What remains:

- **WebGL2 runs on a compatibility layer that is still in development.** `@margoengine/webgl2-compat` (milestones M0 to M7 done) lets core and the optional packages run their WebGPU code on WebGL2 at zero core bytes, and draws the same pixels as native WebGPU in the checks listed in the WebGL2 row. Not finished: M8 (every site demo, docs and the release), the layer's size (92,467 B gzip against a 60,000 B target), the voxel path tracer and XR (they refuse the layer), and the CPU tier's need for `unsafe-eval`. The older `@margoengine/webgl` preview (core meshes, untextured) still ships. See [the WebGL2 compatibility roadmap](webgl2-compat-roadmap.md).
- **Lighting beyond core's sun is optional packages.** Core has one directional light; `@margoengine/clustered/directional` adds up to 16 more (up to 4 shadowed through `LocalShadows`), with IES profiles, projector spots and physical units in the same package, and environment's `HemisphereLight`/`AmbientLight` replace the fixed ambient. Point and spot lights cast shadows through `@margoengine/clustered/shadows` (up to 16 shadowed lights) or through `Clustered.attach(engine, {shadows})` (up to 32). Rectangle area lights (`@margoengine/clustered/area`) cast soft shadows too (up to 4).
- **Core draws views and scenes.** One engine owns one canvas; `engine.views` (or `engine.render({views})`) draws several views in a frame, each with its own camera, rectangle, layers and scene, and `engine.createScene` gives a scene its own meshes, lighting and plugins. Post effects, TAA, shadows, picking and the other packages work per view with per-view history. Planar mirrors and glass (`Reflector`, `Refractor`), a cube render target (`CubeCamera`) and live reflection probes capture other views; `@margoengine/cameras/layers` sets the layer masks views draw. Status per package and the three demos (four-view CAD, split screen, minimap): [multi-view-roadmap.md](multi-view-roadmap.md). The implemented hooks and remaining package work are listed [below](#what-is-missing-or-partial-and-what-to-do).
- **Materials on meshes you build are standard, physical, unlit, Lambert, Phong, toon, normal, matcap, depth, distance, shadow catcher, custom WGSL (`WgslMaterial`) and raw shaders with their own attributes (`@margoengine/shader/raw`).** Any of them can take a per-material `envMap`; textures may be cube, float, 3D, array, KTX2 or Display P3. Physical factors cover clearcoat, sheen, specular, IOR, transmission with screen-space refraction through `@margoengine/materials/transmission`, volume, anisotropy, iridescence and dispersion. glTF loads the same lobes, with iridescence, anisotropy and diffuse transmission through `@margoengine/gltf-pro/extended`. Materials meshes now accept independent UV1 coordinates and geometry groups with material arrays.
- **glTF coverage is nearly complete.** `KHR_animation_pointer` plays node, material, light and camera pointers through `@margoengine/animation/pointer` (iridescence, anisotropy and diffuse transmission through `@margoengine/gltf-pro/extended`, and material variants, are supported). `exportModel` and the data-scene glTF writers write cameras and lights; engine-scene `exportGLB(engine)`, DAE, OBJ and USDZ export do not.
- **Post-processing covers the common passes.** GTAO, SSGI (one diffuse bounce), motion blur, a lens flare, SMAA, glitch and afterimage are in `@margoengine/post`; screen-space reflections (`SSR`) cover core meshes and added glTF-pro, materials, terrain, water and voxel (`VoxelRenderer`). Vignette, chromatic aberration, pixelation, halftone, dot screen, Sobel, sepia and posterize are ready-made `NodePass` effects in `@margoengine/shader/effects`.

Legend. A **†** marks rows where the evidence is the exported symbols, the package README and a non-trivial amount of source code, not a line-by-line read. See [How this was checked](#how-this-was-checked). Rows that work only on WebGPU say "WebGPU only" in their notes.

Two scaling notes from reading core (not measured):

- **Instance buffer size.** Each unique core `Geometry` keeps an instance buffer sized to the meshes that use it, doubling as it grows: 96 bytes per instance on the GPU and the same on the CPU (`Engine.retain` in `packages/core/src/engine.ts`). The earlier per-geometry allocation of the full entity capacity is gone.
- **Geometry and entity caps.** Core caps `Geometry` at 1,000,000 vertices and engines at 8,388,608 entities (initial capacity 1,024, doubled on demand; 351 B of kernel memory per slot). three.js has neither limit. Materials meshes share the 1,000,000-vertex cap.

## Margo extras

These are not in three.js core or its official add-ons. Many have third-party three.js equivalents (noted), which matters for an honest comparison page.

- **Rendering:** cascaded PCSS shadows with a static-caster cache (shadows); clustered forward lighting for up to 1,024 lights (clustered); TAA with motion vectors (taa); Gaussian splats with GPU covariance projection, radix sort and spherical harmonics up to degree 3 (splats; cf. third-party splat viewers); geometry-clipmap terrain with triplanar layers (terrain); GPU particles up to 1,000,000 with obstacles, sorting and sprites (vfx; creative `GPUParticles` is a preset of it); a 100k-blade grass field and a planet renderer (creative); physical day sky plus a stylized night with stars and a phased moon (sky; scenery `SkyMoon` is a preset of it); scene transitions (transitions); GPU scatter with distance LOD (scatter); GPU-driven frustum and Hi-Z occlusion culling with order-preserving compaction and indirect draws for static assemblies (culling); octahedral imposters (lod); vertex animation texture crowds (animation); device-loss recovery that rebuilds every plugin (`Engine.rebootDevice`).
