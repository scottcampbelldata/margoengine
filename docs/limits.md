# Design envelope

Margo is a small WebGPU engine: core plus the stage facade is 19,922 bytes gzip (`npm run measure:size`), and every
other capability is an optional package. That size is a decision, and so are the boundaries below. Each one exists
for one of two reasons: it keeps core small and frozen, or it follows the limits WebGPU guarantees on every adapter
(Margo's device requests none above them, so an app that runs on a laptop also runs on a phone). This page lists every
hard limit, where it starts, what you see when you reach it, and the package or tool that takes you past it.

How to read "Starts at":

- **Enforced**: an exact constant in the source (linked), usually with the test that asserts it.
- **Measured**: a committed result file (linked). Unless a row says otherwise: ASUS Zenbook S 14, Intel Core Ultra 7
  258V with an Intel Arc 140V integrated GPU, Windows 11, Edge 155, AC power, GPU lock held.
- **Not measured**: the boundary exists, but nobody has run the case. No number is given.

Every number here has a row in [whitepaper/claims.md](whitepaper/claims.md) (LIM-001 to LIM-029).

## Scale

| Limit | Starts at | Why | What you see | Escape hatch |
| --- | --- | --- | --- | --- |
| Entities (core meshes, assembly nodes included) | Enforced: 8,388,608 slots (2^23; [kernel.ts](../packages/core/src/kernel.ts), [core-dirty-transforms.test.js](../tests/core-dirty-transforms.test.js)). The store starts at `capacity` (default 1,024) and doubles on demand. Measured ([results-scale-node.json](../examples/package-benchmarks/cad/results-scale-node.json), Node 24, quiet-gated): 352.1 B of kernel memory per slot at 1,048,576 slots (351 B by layout); a static kernel tick costs 3.3 ms at 100,006 entities, 20.2 ms at 499,992 and 41.5 ms at 1,000,012. Above 1,048,576 slots: not measured. | One float32 structure-of-arrays Wasm kernel computes every transform, bound and visibility. It is the reason core is small and fast, and its per-entity cost is linear: about 41 ns per entity per frame even when nothing moves. | Growth is automatic. Past the cap `createMesh` throws `RangeError: Capacity`; `Engine.create` with a larger `capacity` throws `RangeError: Capacity: 1..8388608`. A growth that cannot allocate throws and leaves the store as it was. Before the cap, frame time grows with entity count. | `@margoengine/culling`. `CulledInstances` keeps parts out of the entity store entirely: 0.41-0.55 ms CPU per frame at 89,883 parts, flat in part count ([results-culling.json](../examples/package-benchmarks/cad/results-culling.json)); parts lose picking, hierarchy and section caps. `CulledMeshes` GPU-culls parts that must stay core meshes ([cad-performance.md](cad-performance.md#gpu-culling-of-core-meshes-culledmeshes-handoff-5lb--5mb)); it removes GPU work, not the kernel tick: with `minRadius: 1.5` a 100,008-part orbit draws 11 % of the parts at 138 FPS (core: 29) ([results-5l-after-culled1.5.json](../examples/package-benchmarks/cad/results-5l-after-culled1.5.json)). |
| Nodes and parts per file in packages | Enforced, default 100,000 ([limits.js](../packages/shared/limits.js), [count-limits.test.js](../tests/count-limits.test.js)): glTF nodes ([gltf](../packages/gltf/src/index.ts), [gltf-pro asset.ts](../packages/gltf-pro/src/asset.ts)), `.margo` nodes ([blender](../packages/blender/src/index.ts)), OBJ parts and STEP/IGES meshes ([machinery cad-parser.ts](../packages/machinery/src/cad-parser.ts), [cad-worker.ts](../packages/machinery/src/workers/cad-worker.ts)), `SurfacePhysics` parts and carriers ([machinery surface.ts](../packages/machinery/src/surface.ts)). | Input validation that bounds memory for untrusted files: every node or part becomes a core mesh. | `RangeError: Too many glTF nodes (100001 > 100000; raise the maxNodes option)`; likewise `Too many .margo nodes` (`maxNodes`), `OBJ part limit` and `Too many CAD parts` (`maxParts`), `Too many surface parts` and `Too many surface carriers` (`maxParts`). | The option the error names, up to core's 8,388,608 entities: `maxNodes` on the glTF, gltf-pro and `.margo` loaders, `maxParts` on `loadCAD`/`parseCAD` and `SurfacePhysics.create`; a value outside 1 to 8,388,608 throws `maxNodes must be an integer from 1 to 8388608`. Load time and memory past 100,000: not measured. |
| Buffers per geometry | Enforced: a geometry's vertex, index and instance buffers (96 B per instance) must each fit the device's `maxBufferSize`; core requests the WebGPU default ([renderer.ts](../packages/core/src/renderer.ts)). Not measured. | WebGPU's guaranteed limits, so the same scene runs on every adapter. | `RangeError: GPU buffer limit` when the geometry is first drawn. | Split the geometry, or draw the copies with `CulledInstances`. |
| Shader variants per engine | Enforced: 64 cached pipeline variants ([renderer.ts](../packages/core/src/renderer.ts)). How close real scenes come: not measured. | Bounds pipeline compilation and memory. Variants come from MSAA, target format and shader text. | `RangeError: Shader limit: 64`. | Not needed so far; fewer distinct shader patches per engine. |

## Rendering

| Limit | Starts at | Why | What you see | Escape hatch |
| --- | --- | --- | --- | --- |
| One directional light in core | Enforced by design: core's lighting is one direction and one radiance, plus a colourless scalar ambient. | Every light model beyond one sun is an optional package, so apps that need one sun pay for one sun. | No API for a second sun; ambient has no colour and does not light metals. | `@margoengine/clustered`: up to 1,024 point and spot lights (`RangeError: Expected at most 1,024 lights` past that). `@margoengine/clustered/shadows`: shadows for up to 16 of them ([local-shadows-gpu.json](../examples/package-benchmarks/results/local-shadows-gpu.json)). `@margoengine/clustered/area` (9,177 B gzip): up to 64 rectangle area lights (`RangeError: Expected at most 64 area lights`), unshadowed, no texture bindings ([area-lights-gpu.json](../examples/package-benchmarks/results/area-lights-gpu.json)). Image-based lighting: `@margoengine/environment`. A second directional light: none yet. |
| 16 sampled textures and 16 samplers per shader stage | Enforced by WebGPU's guaranteed minimum; Margo's device asks for no more. gltf-pro's physical material with directional shadows, IBL and local shadows uses exactly 16 (table in the [gltf-pro README](../packages/gltf-pro/README.md#texture-bindings); asserted in [instancing.test.js](../packages/gltf-pro/tests/instancing.test.js)). | Every adapter, phones included, supports 16. Requiring more would make the same app fail on some devices. | A `RangeError` naming the combination, e.g. `gltf-pro: physical material + shadows + environment:lighting + clustered + clustered:shadows + shader patch needs 17 sampled textures per shader stage; this device allows 16`. | Drop one lighting feature for that material, or use the standard material (8 of 16 with everything attached). `VolumetricFog`, SSAO, clustered lights, area lights and light probes (`@margoengine/environment/probes`: one storage buffer; with an environment fallback they take EnvironmentLighting's place and its bindings) add no textures. Texture arrays are planned after 1.0. |
| float32 coordinates | Measured on the GPU ([large-coordinates-gpu.json](../examples/package-benchmarks/results/large-coordinates-gpu.json), 10 mm part, camera 50 mm away): core alone jitters 0.38 px at 1 km and 42 px at 100 km; at 6,000 km the part is not drawn. Per-stage CPU breakdown in [large-coordinates.md](large-coordinates.md). | Core and its kernel store positions and matrices in float32: half the memory and bandwidth of float64, and the format GPUs consume. | No error. Parts shake while the camera moves, small features collapse, specular shifts (2.8° at 100 km), and far enough out geometry disappears. | `FloatingOrigin` in `@margoengine/cameras/origin` (1,258 B gzip, 0 core bytes): 0.019 px jitter at every distance up to 6,000 km, and `engine.pick` hits the part at every distance ([large-coordinates.md](large-coordinates.md#the-plugin)). Vertices or child offsets that are already kilometres from their root inside one asset must be re-centred at export. |
| Transparency | Default: transparent materials and gltf-pro `BLEND` primitives are sorted back to front per mesh; core meshes are opaque. Measured ([oit-gpu.json](../examples/package-benchmarks/results/oit-gpu.json), a 50 % housing over gears orbited 360 × 1°): 13 steps with more than 1 % of covered pixels popping. | Sorting is exact for separate objects and needs no extra targets. | Popping where transparent parts interpenetrate or nest, as the camera moves. | `@margoengine/oit` (2,210 B gzip): 0 popping steps on the same orbit. Weighted blended OIT is an approximation: colour error against exact blending 0.5 / 4.6 / 8.7 (0-255) for 1 / 2 / 4 layers. Transmission and custom blending keep the sorted path; limits in its [README](../packages/oit/README.md#limits-the-wboit-approximation). |
| Screen-space reflections | Enforced by method: only what is on screen reflects. Core meshes and models passed to `ssr.add(model)` show reflections; water, terrain and other custom shaders are reflected but do not reflect. Cost measured on a worst-case glossy floor ([ssr-gpu.json](../examples/package-benchmarks/results/ssr-gpu.json), quiet-gated): 2.2-2.3 ms at 1280×720, 5.8-5.9 ms at 1920×1080. | Reusing depth and colour that are already rendered avoids a second scene pass. Each custom pipeline needs its own capture into SSR's targets. | Reflections fade at screen edges and miss off-screen objects (reflection probes fill in where attached); water and terrain show their own sky reflection. | `@margoengine/post/ssr` (8,529 B gzip) is itself the opt-in. Off-screen reflections: reflection probes in `@margoengine/environment/probes`; SSR removes the probes' own specular only where its ray hits on screen and keeps the probe's reflection elsewhere ([probes-gpu.json](../examples/package-benchmarks/results/probes-gpu.json): off screen the floor equals the frame without SSR, 95th percentile 0/255). Limits in the [post README](../packages/post/README.md). |
| Volumetric fog | Enforced by design: one froxel grid (default 160 × 90 × 64) whatever the screen size, so shadow edges in the fog are about one froxel wide (8 × 8 px at 1280 × 720). Effects measured in [volumetric-gpu.json](../examples/package-benchmarks/results/volumetric-gpu.json). | A froxel volume makes light shafts follow real shadows at a fixed cost per frame. | Particles, VFX, splats and transparent surfaces drawn after it are not fogged; nothing beyond `range`; no local fog volumes or multiple scattering. Errors: `RangeError: Volumetric grid exceeds device limit`; `VolumetricFog replaces environment Fog '<name>': set its enabled = false or remove it`; `VolumetricFog needs scene depth: attach a post capture (Tonemap, Bloom, PostStack, SSAO, TAA) first or pass options.depth`. | `@margoengine/environment/volumetric` (6,658 B gzip) is itself the opt-in: a finer `grid` sharpens edges at a higher cost; `fog.texture` lets custom shaders (particles) sample the fog. Limits in the [environment README](../packages/environment/README.md). |
| Light probes (indirect light) | Enforced ([probes.ts](../packages/environment/src/probes.ts), [probes.test.js](../packages/environment/tests/probes.test.js)): one irradiance volume of at most 4,096 L1/L2 probes (64 per axis) and at most 16 box-projected reflection probes per `LightProbes`. Baked, not dynamic: measured bake of 8 volume probes and one 128 px reflection probe 114-121 ms (diagnostic: other agents' sessions open; [probes-gpu.json](../examples/package-benchmarks/results/probes-gpu.json)). Accuracy in the same file: volume SH within 1.7% of DC against an analytic room. | Baking turns the scene's light into lookups (no ray tracing per frame) and keeps them in one storage buffer, so no texture binding is spent. | Probe light stays as baked until `bake()` runs again; light leaks through walls thinner than the probe spacing (no visibility per probe); mirror-sharp reflections show texel-sized steps near wall edges at the default 128 px. Errors: `RangeError: Invalid irradiance volume: min < max, 1-64 probes per axis (4,096 in total), sh 1 or 2, blend >= 0`, `RangeError: Expected at most 16 reflection probes`, `RangeError: Light probe buffer exceeds device limit`, `light-probes replaces EnvironmentLighting: pass {environment} to LightProbes instead of attaching both`. | `@margoengine/environment/probes` (10,845 B gzip) is itself the opt-in: re-bake on demand, one volume box per room against leaks, a finer `resolution` for sharper reflections. Dynamic GI: none yet. |
| Projected decals | Enforced ([decals.ts](../packages/post/src/decals.ts)): 4,096 decals per `setDecals`, all drawn every frame (no culling); colour only. Cost measured (diagnostic: other agents' sessions open; [decals-gpu.json](../examples/package-benchmarks/results/decals-gpu.json)): 1280 × 720 4x, 1.64 ms without, 1.64 / 1.97 / 6.36 ms with 1 / 16 / 256 one-metre decals. | Screen-space decals need no change to any material shader: one pass reads the scene depth a post capture already provides. | `Decals need scene depth: attach a post capture (Tonemap, Bloom, PostStack, SSAO, TAA) first`; at 4x MSAA decal edges along silhouettes are per pixel; gltf-pro BLEND primitives are tinted with the surface behind them; `multiply` cannot lighten and nothing changes normals or roughness. | `@margoengine/post/decals` (4,118 B gzip) is itself the opt-in; `mode: 'over'` for light-on-dark marks. Normal and roughness decals: none yet. |

## Assets

| Limit | Starts at | Why | What you see | Escape hatch |
| --- | --- | --- | --- | --- |
| STEP and IGES in the browser | Measured ([cad-performance.md](cad-performance.md#step--iges-loading-loadcad), [results-step.json](../examples/package-benchmarks/cad/results-step.json)): OpenCascade is a 7,604,031 B `.wasm` (3,110,912 B gzip); a 441,968 B STEP takes 1,403-1,715 ms from request to model. Enforced ([cad-parser.ts](../packages/machinery/src/cad-parser.ts), [cad-async.ts](../packages/machinery/src/cad-async.ts)): 64 MiB input, 1,000,000 welded vertices, 3,000,000 indices. OCCT runs in 32-bit Wasm (2-4 GB heap, one thread); where a file exhausts it: not measured. | B-rep tessellation needs OpenCascade, a large third-party kernel. It stays out of core and loads only when a STEP or IGES file does. | A 3.1 MB download and seconds of tessellation per file; `TypeError: Invalid CAD input`; `RangeError: CAD unique vertex limit`. | [`margo-convert`](../tools/margo-convert/README.md) converts at build time: `as1-oc-214.stp` (441,968 B) becomes a 68,352 B GLB (25,579 B gzip), validator 0 errors ([margo-convert-diagnostic.json](../examples/package-benchmarks/results/margo-convert-diagnostic.json); sizes are deterministic, its timings diagnostic). The GLB loads with no OCCT. |
| glTF download budget | Enforced: gltf-pro reads at most `maxDownloadBytes` (default 128 MiB, 134,217,728 B) of JSON, buffers and images per load, and decoded accessors, packed geometry and decoded images may each use 4x that (512 MiB by default); `@margoengine/gltf` reads at most 64 MiB ([asset.ts](../packages/gltf-pro/src/asset.ts), [loading.js](../packages/shared/loading.js); [accessors.test.js](../packages/gltf-pro/tests/accessors.test.js)). Khronos ABeautifulGame (a 43 MB GLB whose 33 2048x2048 textures decode to 528 MiB) is over the default image budget. | Bounds memory for any URL an app is handed. | gltf-pro names the option, e.g. `RangeError: glTF images exceed decoded size limit (536870912 bytes; raise the maxDownloadBytes option)`; the light loader throws `glTF download byte budget exceeded` or `glTF buffers exceed 64 MiB`. | gltf-pro's `maxDownloadBytes` option (ABeautifulGame loads with 160 MiB, [khronos-gallery.js](../examples/khronos-gallery.js)); for the light loader, use gltf-pro. |
| Vertices per primitive | Enforced: gltf-pro takes up to 1,000,000 vertices per primitive (index accessors are bounded only by the decoded budget); the light `@margoengine/gltf` loader up to 1,000,000 vertices in total ([accessors.test.js](../packages/gltf-pro/tests/accessors.test.js): 1,000,002 indices decode, 1,000,002 vertices are refused). | Vertex buffers are also bound as storage buffers, and indices pass through float32, exact up to 2^24. | gltf-pro names the location: `glTF mesh 0 "part" primitive 0: Expected bounded triangle geometry`; the light loader: `RangeError: glTF exceeds one million vertices`. | gltf-pro instead of the light loader lifts the total; a primitive over 1,000,000 vertices must be split at export (for CAD, a coarser `margo-convert --linear-deflection`). |

## Platform

| Limit | Starts at | Why | What you see | Escape hatch |
| --- | --- | --- | --- | --- |
| WebGPU first | Enforced: `Engine.create` uses WebGPU unless the app passes a fallback ([engine.ts](../packages/core/src/engine.ts), [webgl.test.js](../packages/webgl/test/webgl.test.js)). | One backend keeps core at 19,922 B; culling, particles, sections and most effects are compute or WebGPU-only work. | `Error: WebGPU unavailable` (no fallback) or `Error: adapter unavailable` (`backend: 'webgpu'`); on the WebGL2 path, `engine.pick` throws `WebGPU required`. | `@margoengine/webgl` (2,156 B gzip, `Engine.create(canvas, {backend: 'auto', fallback: webglRenderer})`): a basic preview of core meshes, flat-shaded with one directional light, no textures, effects or picking. Real-browser checks in [gates-browser-tests.json](../examples/package-benchmarks/results/gates-browser-tests.json). Most rendering packages stay WebGPU-only. |
| Content Security Policy | Enforced by the browser: core compiles its Wasm kernel, so `script-src` needs `'wasm-unsafe-eval'` (as do the machinery kernel, OCCT, Draco and Basis). Nothing needs `'unsafe-eval'`, workers included: the Draco/KTX2 decoder worker and the STEP/IGES CAD worker load their Emscripten code with `importScripts`, and the build replaces the `new Function` wrapper generators in the Basis and OCCT glue with closures, output byte-identical ([no-eval-workers.test.js](../tests/no-eval-workers.test.js)). No COOP/COEP. Checked with zero violations on Edge, one policy on the page and every worker ([csp-check.json](../examples/package-benchmarks/results/csp-check.json)). | Wasm is how the kernel stays small and fast. | Without `'wasm-unsafe-eval'`, `Engine.create` rejects ("Compiling or instantiating WebAssembly module violates the following Content Security policy directive") ([csp-check-negative.json](../examples/package-benchmarks/results/csp-check-negative.json)). | Headers for Cloudflare Pages, Netlify, Vercel and Nginx in [deploying.md](deploying.md). A Draco, Basis or OCCT build you substitute for the bundled one may still call `new Function` (three.js's Basis transcoder does) and then needs `'unsafe-eval'` for its worker. |
| No visual editor | By design: Margo is code-first. | An editor is a product of its own; the engine stays a library. | Scenes are built in code or authored in another tool. | Author in Blender and export glTF or `.margo` (`@margoengine/blender`, `tools/blender-addon`, [guides/blender-game.md](guides/blender-game.md)); inspect at runtime with `@margoengine/inspector` and its `/frame` debugger; move objects with `@margoengine/gizmo`. A Margo Studio editor is planned after 1.0 ([margo-studio.md](margo-studio.md)). |
| Tested hardware | Every committed real-GPU result comes from one machine: the Intel Arc 140V laptop above, in Edge 155. Phones: the demos were run by hand on an iPhone (Safari), with no scripted run or committed result; a Galaxy S23 Ultra report of a slow island demo is unresolved. | One developer, one laptop so far. | Behaviour elsewhere follows WebGPU's guarantees but is unverified. | Untested: discrete NVIDIA and AMD GPUs, Apple silicon Macs, Android devices other than the S23 report, Linux, ChromeOS. Results from these are welcome; [reproduce.md](whitepaper/reproduce.md) has the commands. |
| Browsers | Verified: Edge 155 (Chromium) on Windows, automated (real-GPU suites, visual regression, CSP). iPhone Safari: run by hand only (above). Firefox: not verified. macOS Safari: not verified. | Same as above. | Where a browser lacks WebGPU, `Engine.create` reports it (see "WebGPU first"). | Chrome uses the same Chromium engine as Edge; the automated suites run in Edge. CSP behaviour in Firefox and Safari is unverified. |
