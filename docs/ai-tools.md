# Using Margo with AI tools

AI coding tools write good Margo code when they read the right pages and check what they wrote. Margo gives them
three ways in, from least to most setup.

## 1. Point the tool at llms.txt

[`llms.txt`](https://margoengine.com/llms.txt) follows the [llms.txt convention](https://llmstxt.org): a title, a
summary, and sections of links with one-line descriptions (guides, one README and one API page per package,
examples). [`llms-full.txt`](https://margoengine.com/llms-full.txt) is the same material as one text file: the
guides in full and each package README (long ones cut, with a link to the rest).

- **Cursor:** Settings, Indexing and Docs, Add Doc, paste `https://margoengine.com/llms-full.txt`. Then write
  `@Docs Margo` in a chat.
- **Claude Code and Claude Desktop:** ask the tool to read `https://margoengine.com/llms.txt` first, or paste the link
  into the chat. Add a line to your project's `CLAUDE.md`: `Margo Engine docs for AI: https://margoengine.com/llms.txt`.
- **Copilot and other chat tools:** attach `llms-full.txt` as a file, or paste the link.

Both files are generated by `node scripts/build-llms.mjs` from the package READMEs, the `api/` reports and `docs/`.
The test `tests/llms.test.js` fails when either is stale. Run the generator after relevant documentation or API
changes; it only updates the files and never commits them.

## 2. Run the MCP server

[`@margoengine/mcp`](../packages/mcp/README.md) is a Model Context Protocol server that runs locally over stdio. It
answers from the docs of the version you installed, and it type-checks code against your project's real Margo types.

| Tool | Use it to |
| --- | --- |
| `search_docs` | Find the API or README section for a task or an exact name. |
| `list_packages` | See which optional package provides a feature (core is frozen; features are packages). |
| `get_package` | Read one package's README or API report. |
| `list_examples` | Find a runnable example before writing one. |
| `check_snippet` | Type-check a snippet strictly against the installed packages. |
| `port_to_margo` | Map a three.js class or task (`OrbitControls`, `InstancedMesh`, "shadow map") to the Margo package and calls, with status, limits and both libraries' code, from the [parity matrix](threejs-parity.md) and [Coming from three.js](from-threejs.md). |
| `explain_error` | Explain a pasted Margo error (the message, its `errors#<id>` link, the id or the `MargoError` code) with its cause and fix from the [error help page](https://margoengine.com/errors). |
| `render_snippet` | Only with `--render`: run a snippet on the GPU in Node and see the PNG it draws. Needs `@margoengine/headless`, `@margoengine/stage` and `webgpu` in the project; runs code with your rights. |

The server also offers every package README and API report and every docs page as resources
(`margo://packages/<id>/readme`, `margo://packages/<id>/api`, `margo://docs/<path>`, `margo://readme`), which a
client can attach to a conversation without a tool call, and four starter prompts: `start_scene`, `port_code`,
`fix_error` and `add_feature` (in Claude Code, `/mcp__margoengine__start_scene` and so on). Each prompt names the
tools to use, in the order below.

Setup (full steps in the [package README](../packages/mcp/README.md)):

```sh
npm i -D @margoengine/mcp typescript margoengine
claude mcp add margoengine -- npx -y @margoengine/mcp        # Claude Code
```

Claude Desktop and Cursor take the same command in a JSON config file: `command` `npx`, `args`
`["-y", "@margoengine/mcp"]` (Claude Desktop also needs `"--root", "/path/to/project"`).

A good loop for an assistant, and the one the server's own instructions suggest: `search_docs` or `list_packages`,
then `get_package` for the package it will use, write the code, then `check_snippet` and fix what it reports before
showing the answer. When the user brings three.js code, `port_to_margo` first, once per class it uses; when they paste a Margo error, `explain_error`.

## 3. Give the assistant a project rule

Short rules in `CLAUDE.md`, `.cursor/rules` or `.github/copilot-instructions.md` stop the most common mistakes:

```md
This project uses Margo Engine (WebGPU). Docs for AI: https://margoengine.com/llms.txt
- Core (`@margoengine/core`) and the stage (`margoengine`) are small; every feature is a separate optional package.
  Find it with the margoengine MCP tool `list_packages` and import only what you use.
- `margoengine/<name>` and `@margoengine/<name>` are the same module.
- Units are metres and glTF conventions (Y up, right-handed).
- Anything that loads or waits takes an `AbortSignal`; errors carry a `code` (branch on it, not the message).
- Run the margoengine `check_snippet` tool on Margo code before presenting it.
```

## What the tools cannot do

- **Render without a GPU binding or a browser page.** `render_snippet` draws in Node through the `webgpu` binding,
  so it needs that package and a GPU (or a software adapter through `gpuFlags`). Code that needs a page (DOM input,
  `createStage('#canvas')`, a frame loop) does not run there: write the snippet against the stage it is given.
- **Run your code by default.** `check_snippet` only compiles; `render_snippet`, which runs code, is offered only when
  the server is started with `--render`.
- **Port by meaning.** `port_to_margo` matches the words and name parts of the matrix rows. A class the matrix does not
  list gets no row; the answer says so and points at `search_docs`.
- **Watch the docs change.** Resources come from the snapshot the package was built with, so there are no
  subscriptions or change notifications; update `@margoengine/mcp` to get newer docs.
- **Know a package you have not installed.** `check_snippet` resolves imports from your `node_modules`; an import of a
  package that is not installed is reported as an error, which is the right answer for an app that does not have it.

## Keeping it current

| File | Made by | Checked by |
| --- | --- | --- |
| `site/llms.txt`, `site/llms-full.txt` | `node scripts/build-llms.mjs` | `tests/llms.test.js` (in `npm run verify`) and `node scripts/build-llms.mjs --check` |
| `margoengine.com/llms/...` pages | `scripts/build-site.js` | `npm run site:check` |
| `@margoengine/mcp` corpus | `packages/mcp/scripts/build-corpus.mjs`, at package build | `packages/mcp/tests/` |
