# PDF export and math labels

Optional entries `@margoengine/sciviz/pdf` and `@margoengine/sciviz/math` own publication output. Neither core nor stage imports either entry. The existing font loader supplies clean-room TrueType outlines; a caller supplies an OutlineFont so font licensing, coverage and selection are explicit.

`svgToPDF(svg, options)` writes PDF 1.7, one page with a page tree, byte-addressed cross-reference table, Flate-compressed content and image streams, UTF-16BE document information and optional JSON provenance. `exportPDF(figure, options)` converts the figure's current SVG. The default physical size is CSS pixels at 96 dpi; widthMM sets the page width and preserves aspect. Labels are paths, not substituted PDF fonts. fontForText optionally selects a font by SVG family and weight. AbortSignal is checked before work, across graphics traversal and after asynchronous compression/image decoding; its reason is preserved.

The writer preserves every operation emitted by current Figure.toSVG and exportVector: paths, polylines, rectangles, circles, text, round caps/joins, dashes, fill/stroke alpha, nested SVG viewports, affine transforms, plot clipping, multi-stop axial gradients, and embedded PNG frames. Images are decoded to RGB with a separate grayscale soft mask when needed. Quadratic glyph curves become mathematically equivalent cubic curves. Metadata and images never affect vector ordering. External image URLs, unknown drawing elements and unsupported SVG operations fail explicitly rather than disappear. This is a figure-SVG converter, not a general SVG renderer: arbitrary filters, masks, patterns, radial gradients, use elements, CSS stylesheets, text spans and externally styled SVG are outside its input contract. Figure output does not contain them. Embedded PNG/JPEG/WebP images use browser image decoding; vector conversion and compression use web APIs, with no headless browser process inside the writer.

`parseMath` accepts a bounded inert TeX subset. `mathML` returns native accessible MathML. `renderMath` returns the same expression as MathML plus an SVG with font-outline paths and width, height and baseline. `mathLabel` replaces an existing HTML label and retains its outline for export. `addMathLabel` adds an owned figure overlay at CSS-pixel x/y; it participates in PNG, SVG and PDF and removes on early disposal or figure disposal. The canvas parent should be positioned, as in the existing demo view. The font size defaults to 16 CSS px; SVG colour defaults to currentColor, and figure overlays default to the figure text colour.

Syntax: braced groups, frac/dfrac/tfrac, sqrt with optional index, both subscript/superscript orders, lower/upper Greek and common variant letters, arithmetic/relational/set/arrow operators, sums/products/integrals, named trigonometric/logarithmic operators, escaped literals, explicit spaces, plain text/roman/operatorname, hat/bar/overline/underline/vec/dot/ddot/tilde accents, left/right delimiters, and matrix/pmatrix/bmatrix/Bmatrix/vmatrix/Vmatrix/cases/aligned environments. Unknown commands, mismatched groups/environments and duplicate scripts fail. No macros, HTML evaluation, font loading or import side effects. Limits: 16384 input characters, 64 grammar nesting levels; PDF SVG traversal has 128 nested levels. Missing Unicode glyphs are errors, never silently replaced by boxes.

MathML uses the browser's native math layout. Outline layout uses em-relative axis/gaps/script sizes, baseline-clearance constraints, explicit radical/accent rules and stretched delimiter outlines. It covers all requested syntax classes; it is not a pixel-identical TeX or OpenType MATH layout engine. Font-specific MATH constants, italic correction and assembled delimiter variants are appearance refinements retained for the finish phase. Outlined text is not searchable PDF text. Journal font and embedded subset-font alternatives can be added without modifying this path-based contract.

## Real data and correctness evidence

examples/sciviz-publication.html plots all 3441 published GW150914 Hanford observed samples from LIGO Figure 1, with time in seconds, strain units 10^-21 and the formula h(t)=Delta L(t)/L. The asset source.json records source, licence and SHA-256. The standard DejaVu Serif 2.37 binary is unchanged; its full licence is adjacent. No scientific data were invented or smoothed.

CPU tests cover grammar structure, every requested syntax family, escaping, bounded rejection, glyph coverage, PDF xref byte offsets, page tree, physical size, Unicode metadata, compressed streams, exact quadratic conversion, transforms, clipping, axial shading, alpha and cancellation. The browser check runs native WebGPU and the WebGL2 layer, checks formula paths in the actual figure SVG, native MathML, PNG overlay export and disposal, and writes real PDF/SVG/PNG artifacts. An independent MuPDF 1.28.2 audit opens all six generated PDFs without repair: LIGO has 12 path drawings and zero images on each backend; the formula matrix has one compound path and zero images. The mixed-image fixture retains one image plus its soft mask. Independent pixels verify image RGB orientation, half-transparent black (126,126,126) on white, half-red clipping (255,128,128), white outside the clip, and red/green/blue axial-gradient endpoints. No timing or speed claim is made.

## Clean-room basis

Compared the PDF path and subset-font alternatives: paths reuse owned font outlines and avoid font-embedding substitution while keeping every scientific symbol explicit. Compared native MathML layout, TeX box rules and font-specific OpenType MATH: native MathML serves HTML accessibility; deterministic boxes and outlines serve vector exports. Sources, all descriptions/specifications rather than implementation code:

- Adobe Systems, PDF Reference, sixth edition, version 1.7 (2006), https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.7old.pdf . Page trees, cross references, graphics operators, FlateDecode, shading functions, images/soft masks and information dictionaries.
- Donald E. Knuth, The TeXbook, appendix G (1984), public syntax and layout descriptions as discussed by MathML Core and Vieth below; https://www-cs-faculty.stanford.edu/~knuth/abcde.html . Grouping, fractions, scripts and radicals; no TeX implementation source consulted.
- David Carlisle and Frederic Wang, editors, W3C MathML Core (2025), https://www.w3.org/TR/mathml-core/ . Presentation markup, script clearance, fraction/radical boxes, accents and tabular layout.
- Ulrik Vieth, OpenType Math Illuminated, TUGboat 30(1), 22-31 (2009), https://tug.org/TUGboat/tb30-1/tb94vieth.pdf . Comparison of TeX font parameters and OpenType math parameters; font-specific refinements are explicitly not claimed here.
- Microsoft, The mathematical typesetting table, OpenType 1.9.1 (2024), https://learn.microsoft.com/en-us/typography/opentype/spec/math . Glyph assemblies and math constants; explains the remaining font-specific appearance differences.
- W3C SVG Working Group, Scalable Vector Graphics 2, Paths and Painting (2018/living specification), https://www.w3.org/TR/SVG2/paths.html and https://www.w3.org/TR/SVG/painting . Path, fill, stroke and alpha semantics; https://www.w3.org/TR/SVG/latest/pservers.html for gradient stops.

No rival engine, math-typesetter source or paper companion code was read or copied. No Rust/Wasm rewrite is justified for this bounded parser/object writer; no speed measurement or gain is claimed.
