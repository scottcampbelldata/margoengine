# Accessible scientific figures

Batch 178 job 5 adds the optional `@margoengine/sciviz/a11y` entry. Importing it installs no listeners, globals, DOM or audio. Call `attachAccessibility(figure, options)` explicitly, await `handle.ready`, and dispose the handle or its owning figure. An AbortSignal cancels data readiness, adapters, GPU reads and listening. Custom adapters must also observe the passed signal to stop their own work.

The canvas becomes a named keyboard application with instructions and a visible focus outline. Left/right move records, up/down change series, Home/End visit endpoints, and Tab leaves. Focus moves a white/black marker without changing selection or panning the camera. Navigation consumes these arrows before ordinary camera key handlers. A polite live region outside the closed menu announces the current series, record, coordinates and scalar value. Date-axis coordinates use ISO timestamps. The generated description gives total and missing counts, observed ranges, extreme record locations and an online least-squares rising/falling/flat trend. A trend is descriptive, not a significance or physical-causality claim.

The native HTML data table is pageable (50 rows by default, configurable from 1 to 1000) with its complete logical row count, absolute row indices and previous/next controls. Paging bounds the DOM, never the data. Native line/scatter/bin adapters retain their data coordinates, including the optional chart controller's original secondary-axis values. Surface and volume readValues preserve borrowed CPU precision or explicitly read GPU scalar data in source units; voxel/grid coordinates use physical bounds. Application-defined layers can supply lazy AccessibleSeries adapters and call refresh after in-place edits. Unsupported layer kinds receive a factual bounds/layer-count description; an application adapter is required for their full table. The example integration explicitly attaches the optional view to every registered scientific figure; standalone DOM/SVG charts retain their native HTML semantics.

High contrast uses black/white chrome and a gray grid. It does not recolour measured-data scales or imply that every categorical pair is distinguishable. Figure themes are copied, validated and saved in portable specifications. The initial media defaults are prefers-contrast:more/forced-colors:active and prefers-reduced-motion:reduce. Reduced motion suspends timeline frame delivery and engine frame pacing; explicit renders and data navigation still work. Turning the preference off or disposing the view restores the prior pacing and theme. Existing playback retains its options, promise and AbortSignal while suspended; a previously stopped engine stays stopped. Optional UI is an overlay, so attaching it does not resize the plot or add controls to publication exports. It is cleaned up with the figure.

Sonification is explicit: Listen maps values logarithmically between 220 and 880 Hz and observation time to a 10-second listening interval by default. Missing observations keep their own silent slots, constant data uses the midpoint, and optional strictly increasing source times preserve irregular spacing. The default 100000-record scheduling budget rejects larger series rather than silently discarding points; applications can supply a window or increase maxPoints. Volume is 0.05 by default, duration is (0,600] seconds and pitch is within [20,20000] Hz. playSonification uses one oscillator/gain pair, closes owned AudioContexts on completion/cancellation/failure and leaves borrowed contexts open. No sound starts on import or attachment. Sonification supplements numerical tables and labels; it does not establish detection efficacy or replace subject-matter review.

Existing frozen assets, source hashes and public-domain licences are retained. Unit tests cover summary arithmetic, exact missing slots, pitch/time endpoints, borrowed audio lifetime, suspended-resume cancellation, keyboard capture, empty series, reattachment, table paging, adapter cancellation, theme isolation and portable state. a11y-browser runs real Web Audio, source-precision and GPU-read tests on WebGPU and WebGL2. chart-polish-browser checks the interactive legend is a group of pressed buttons with actual 24px targets.

The script takes loaded-page snapshots after accessible source readiness at 1440 x 1000; no accessibility audit is disabled. A11Y_PAGES optionally selects comma-separated filenames for diagnosis. Full machine-local Lighthouse JSON is under test-results/sciviz-a11y/lighthouse; the durable score ledger is docs/whitepaper/results/batch178-a11y.json. Lighthouse 100 is an automated audit result, not a manual screen-reader certification or a claim of complete WCAG conformance.

## Clean-room basis

Compared these primary sources before implementation, without reading companion or rival source:

- Jonathan Zong, Crystal Lee, Alan Lundgard, JiWoong Jang, Daniel Hajas and Arvind Satyanarayan, Rich Screen Reader Experiences for Accessible Data Visualization (2022), https://vis.csail.mit.edu/pubs/rich-screen-reader-vis-experiences/ . Hierarchical exploration, summaries and direct datum access motivate the explicit series/record model.
- Frank Elavsky, Lucas Nadolskis and Dominik Moritz, Data Navigator: An accessibility-centered data navigation toolkit (2023), https://arxiv.org/abs/2308.08475 . The independent input/navigation layer motivates focus separate from selection, with semantic DOM output and adapters.
- J. Tucker Brown, C. M. Harrison, A. Zanella and J. Trayford, Evaluating the efficacy of sonification for signal detection in univariate, evenly sampled light curves using astronify (2022), https://arxiv.org/abs/2209.04465 . Time-to-time/value-to-pitch is combined with explicit numerical access; the study's task/training limits prohibit claiming universal detection efficacy.
- W3C WAI, ARIA Authoring Practices: Developing a Keyboard Interface (accessed 2026-11-10), https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/ . Logical navigation, visible focus and a way to leave the widget define the keyboard contract.
- W3C, Web Content Accessibility Guidelines 2.2 (2023), https://www.w3.org/TR/WCAG22/ . Semantic landmarks, keyboard operation, focus, reduced motion and 24px targets inform the demos and controls.
- Paul Adenot and Hongchan Choi (editors), Web Audio API (W3C Recommendation, 2021), https://www.w3.org/TR/2021/REC-webaudio-20210617/ . AudioParam scheduling and explicit node/context lifetime define playback and cancellation.

The papers motivate interaction design; WAI and Web Audio specify browser contracts. The implementation, tests, markers, descriptions and scheduling code are written independently for Margo.
