Package sizes

Every number on this page was measured from the build of commit 2959f9aeb, when this page was generated. Raw is minified ES2022 code; min+gzip is the same code gzipped. Each entry is bundled on its own with other packages left external, because your app shares them. Workers and Wasm that load later are listed with the call that loads each.

A basic glTF scene on the network

The five-line stage app (createStage('#scene'), then addGLTF(app, './model.glb') of a 1,332 B cube), built for production with Vite and opened in msedge 157.0.4341.42 headless. The browser's network log held exactly these files. Transferred is what crossed the wire: the body as served (the preview server gzips JavaScript) plus response headers. Raw, gzip and brotli are the built files.

The build emitted nothing else: no Wasm, no worker and no other pack, because the app imports only the glTF entry. Each other stage feature is its own entry (margoengine/stage/sky, /particles, /effects, /environment, /shadows, /xr) that loads its pack on the first call, listed below. Reproduce with node scripts/basic-scene-network.mjs: it fails if the page fetches any other file.

Loaded later, and what loads it

Every file a package fetches or compiles on its own after the entry you import: the stage's packs, workers and Wasm runtimes. Workers, glue scripts and .wasm files are measured as served, because your bundler copies them as they are. The stage's packs, the BVH module worker and the Rapier module are bundled and minified like the entries below (the packs with core left out, since the stage already loaded it). Rapier inlines its Wasm, so it makes no separate .wasm request.
