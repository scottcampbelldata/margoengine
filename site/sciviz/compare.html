Scientific visualization against the web rivals

Batch 182, 2026-11-10. This page compares @margoengine/sciviz with the scientific and charting libraries people use on the web today. It has four parts: features, measured scenes, accuracy against closed-form answers, and losses. Nothing here is a speed claim. Every timed number waits for the quiet-machine run (see "Losses and pending timing"). The public page is site/sciviz/compare.html (site/sciviz/compare.html).

How to read the feature rows

  • Margo cells name the test file or README section that proves the feature. Paths are relative to packages/sciviz/.
  • Rival cells say what the rival's public documentation lists, with the URL, the version and the date it was read. We never read rival source code. Six rivals were also installed and run as black boxes; their pinned versions are in scripts/sciviz-compare/manifest.mjs.
  • "Desktop tools" (ParaView, VisIt, 3D Slicer, yt) show what scientists expect from experience. They are an expectation, not a score, and they are not rivals of a web library.
  • "Not found" means we found no feature, export or test with that name in Margo. It does not mean the work is impossible. Those gaps are listed at the end.

Rival documentation read on 2026-11-10: VTK.js 38.0.5 (API docs), Plotly.js 4.2.0 (reference), deck.gl 9.4.1 (layers), ECharts 6.1.0 and ECharts-GL 2.1.0 (features), regl-scatterplot 1.16.0 (README), Cosmograph 2.5.1 (config reference), Neuroglancer (data sources), Bokeh (linking), Vega-Lite (selections, transforms), ParaView Glance (readers). Unversioned rows are the documentation current on that date.

Measured scenes

npm run sciviz:compare runs each case in one headless page: Margo and one rival draw the same data at 256 x 256 pixels with the same camera, background and colour. Six rivals are installed outside this repository under the engine-bench folder (MARGO_ENGINE_BENCH overrides it). Only their documented public APIs are called.

Image differences are observations, not pass marks. They come from different antialiasing, point and line rasterization, interpolation and storage precision. They are not used to accept or reject a run. The graph row has the largest difference: Cosmograph draws links dimmer than the shared colour at width 1 and adds an attribution overlay outside its canvas; the node layout matches.

Explicit differences in work

  • Volume: Margo captures scene depth and composes the volume with opaque geometry through its multisample frame graph: 9 render passes, 5 draws, 3 buffer writes per frame against one VTK.js draw. This supports clipping volumes against geometry and stays. Margo stores normalized scalars as half floats; VTK.js receives float32.
  • Plotly: both sides go through PNG export and decode in that pairing, because Plotly's static image route is its documented capture path.
  • Cosmograph: it keeps its own animation loop; two idle animation frames record its draws with no frame requested (work.idleTwoAnimationFrames in the JSON). That work also runs during Margo's samples.
  • ECharts-GL and regl-scatterplot run on WebGL1 contexts; deck.gl, VTK.js and Cosmograph on WebGL2; Margo on WebGPU.

Not found in Margo today

MinIP, multi-component and general multi-volume compositing, the threshold, plot-over-line, integrate, resample, warp and connectivity filters, Zarr Blosc and Zstandard, and a SPLOM test. These are listed in docs/known-bugs.md under "Sciviz comparison gaps".

Reproduce 

npm run build:packages
npm run sciviz:compare -- --runs=1            # smoke: installs the rivals outside the repo, no clock
npm run sciviz:compare -- --list              # every case and scale
node --test packages/sciviz/tests/analytic-references.test.js packages/sciviz/tests/transfer.test.js

The timed run needs the active speed phase (MARGO_SPEED_PHASE=active) and takes the GPU alone; see reproduce.md (docs/whitepaper/reproduce.md).
