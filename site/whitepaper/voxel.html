Where it stands today

  • Not released. A Windows portable build exists but is unsigned and unpublished, the source repository is private, and there is no hosted version yet.
  • One platform verified. Windows 11, Edge 155 and an NVIDIA RTX A6000, plus a Ryzen 9 9950X for the CPU benchmarks. macOS, Linux, phones and other GPUs are not verified.

0Abstract

Margo Voxel Studio is a voxel editor that runs in a desktop browser with WebGPU and as a Windows desktop app from the same production build. Files and recovery data stay on the local device. It is written clean-room: MagicaVoxel, the most widely used free voxel editor, serves only as a black box we test against, and none of its program files, shaders or bundled models are part of the project.

The app owns its interface, documents and undo history. Everything that is engine work (voxel grids and brushes, picking, meshing, the .vox codec, glTF export, lightmap baking, and a progressive path tracer) comes from Margo Engine's public packages, consumed as 19 unmodified, hash-pinned archives. This paper describes that split, the path tracer and its denoiser, how closely it reproduces MagicaVoxel's renders of the same files, how exports fare in Godot, Unity and Unreal, and what is still open. Every number names its source file. The engine itself is described in the Margo Engine whitepaper.

1The editor

Modeling
Attach, erase, paint, pick and select; voxel, face, box, line, sphere and flood brushes; XYZ mirroring; undo and redo; clipboard; shrink, invert, wrap and repeat, nearest-neighbour scaling, arbitrary rotation, directional morphology and enclosed-air fill. Palette-index and six-connected selection with replace, add and subtract.
Scenes
Named objects, parent groups, coloured layers, local transforms and pivots. Instances from imported .vox scenes share editable geometry.
Animation
Step and linear transform keys, independent geometry frames, per-object clocks, scrubbing and playback, and animated GLB export. An 18-joint humanoid skeleton generator exports a real glTF skin as a starting point; bone animation and production weight painting are open.
Palettes
Independent indexed palette banks per model, live grading that keeps the source colours, presets and shading ramps.
Procedural
A cancellable voxel-expression language with numeric parameters, deterministic noise and iteration snapshots, applied as one undo step. GPU shader tools and authored surface graphs use Margo Engine's own APIs. Original templates include six articulated showcase scenes (a citadel, a dragon, an interceptor with an opening canopy, an industrial mech and others).
Files
Native .margo projects with crash recovery, .vox import and export, sprite-sheet slices from PNG, WebP or JPEG, PNG viewport capture.
Output
Worker-side GLB export with greedy meshing, a palette atlas or vertex colours, optional corner ambient occlusion and crease-controlled normals; OBJ; path-traced PNGs, frame sequences, turntables and sprite-atlas ZIPs, all cancellable.

2How it is built

The rule that keeps the split honest: engine source is read-only for the app. When a public engine API cannot carry a feature, the app either keeps its existing behaviour frozen or disables the piece, and records it as a numbered engine gap; the fix then lands in the engine, never as a private patch. The app does not copy, extend or rebuild engine code. The engine archives are built from one engine commit and recorded with their hashes, and a check confirms all 38 import paths resolve.

  • Stack: React 19, Vite 8, TypeScript 7, Electron 44 with context isolation, the sandbox on and no Node integration in the page. Browser tests run in real Edge through Playwright.
  • Local first: the static build caches its assets for offline use after the first load. Recovery saves are one atomic IndexedDB transaction, and .margo is versioned JSON.
  • Off the main thread: meshing, sprite slicing, texture baking and GLB export run in workers; the path tracer is a separate chunk loaded when Render mode opens.

At the last recorded check (2026-10-21) the app passed 615 of 615 unit tests and 54 of 54 real-Edge browser tests against the exact engine bytes it ships.

3The path tracer

@margoengine/voxel-pathtracer attaches to an engine and, while enabled, replaces the frame with a path-traced image of the voxel scene through the engine camera, refining every frame up to a sample budget. Turning it off returns the raster frame bit for bit. It also renders off-screen PNGs and float images and answers ray picks against the same scene. It is written from public rendering literature, and its README cites each source.

How it works

  • Models are packed into 8³ bricks (empty, uniform or 512 bytes) and walked with Amanatides and Woo's grid traversal, first over bricks, then over voxels inside mixed bricks. A bounding volume hierarchy (binned surface-area heuristic) finds instances, and rays move into each model's space by its inverse transform.
  • Unidirectional path tracing with next-event estimation for the sun, emissive faces, area lights and the environment map, combined with BSDF sampling by multiple importance sampling, and Russian roulette.
  • GGX microfacets with height-correlated Smith masking, sampled from visible normals; Kulla-Conty energy compensation for rough metals, with the albedo tables integrated once per device on the GPU by the tracer's own sampling code.
  • Homogeneous participating media, an analytic daylight sky (Preetham et al.), importance-sampled HDR environments, single-wavelength dispersion in glass, depth of field with round and polygonal apertures, and instance motion blur.
  • Light through smooth glass and off mirrors is found by solving refraction and reflection at planar voxel faces for shadow rays, weighed against ordinary paths through the same chain. Voxel scenes make this tractable because every interface is axis-aligned and flat.

Correctness checks

The tests compare the tracer with closed forms and with itself. Error against a 16,384-sample reference falls 0.0216, 0.0114, 0.0058, 0.0030 at 16, 64, 256 and 1,024 samples, the 1/√N rate of an unbiased estimator. A floating glass cube's shadow and caustic computed with light sampling matches the same light found by path sampling within 0.31% (IOR 1.5) and 0.40% (IOR 1.33). Equal seeds give bit-identical images.

4The denoiser

The denoiser is a classical filter, not a learned one: an edge-avoiding à-trous wavelet filter on albedo-demodulated radiance, with variance-guided luminance stops and a plane-distance geometric stop. In the viewport it accumulates over frames by reprojection and clamps history in YCoCg. At object, material and texture edges it weighs the filtered estimate against the raw mean by their estimated errors, so where the samples already resolve detail, filtering does not blur it.

The app holds it to 72 quality gates: three original 96×72 fixtures, each with an independent 65,536-sample reference, rendered at 4, 16 and 64 samples with three seeds, and scored in both linear RGB and log(1 + radiance). A gate passes when the denoised image has no overall or flat-area regression against the raw image at the same sample count, and at most 3% regression on geometry and texture edges. The thresholds and fixture hashes have not changed since they were set.

On the engine's own scenes, averaged over four seeds against 131,072-sample references, it lowers RMSE 2.46x, 2.32x and 2.24x at 4, 16 and 64 samples on the material scene and 2.20x, 2.09x and 2.03x on a caustic scene. These gates compare against raw output, not against Intel's OIDN, so they say nothing about how we compare with it.

5Opening MagicaVoxel files

People who already have a library of .vox files should be able to open them and see what they saw before. So the tracer has an import look that maps a .vox file's render settings onto its own, and we measure how close that gets.

Method

MagicaVoxel 0.99.7.2 is treated strictly as a black box. We write our own .vox scenes with our own writer of the published format (including the default render settings, which since 2026-10-20 come from our writer, not from a file MagicaVoxel saved). MagicaVoxel renders them through its interface and we save its snapshots; we render the same files and score the two images pixel by pixel. Its code, shaders and configuration were never read. Its renders stay on our machine and are not redistributed, so anyone checking these numbers needs their own copy of MagicaVoxel and our scene scripts.

Still open: some tiles next to subsurface blocks under the sun are 7-16 levels off, and subsurface is fitted at one density only; glass over a lit floor comes out 1-2 levels bright; grid lines match on 92.7-94.6% of pixels; depth of field never showed in MagicaVoxel's snapshots, so it is not compared.

How fast

Ours renders each of the six scenes at 960×800 and 1,024 samples in 1.7-2.2 s on the RTX A6000. MagicaVoxel could only be timed by stopwatch on its progress bar, so we publish no speed comparison.

docs/parity/magicavoxel-parity.md (app), "Current scores"

Where MagicaVoxel is ahead: it is a complete, mature, free editor, and its renderer has years of use behind it. We have compared on one PC and one browser.

File limits

The engine's codec reads and writes versions 150 and 200 of the published format, and an unedited file writes back byte for byte. On export the app merges palette banks into one .vox palette when the occupied colours fit in 255 slots, splits large models into occupied buckets of at most 256 per axis, and refuses what .vox cannot hold (per-object clocks, procedural graphs, placements that are not whole-cell moves and quarter turns) rather than rounding it into something different.

6Into game engines

GLB export uses greedy meshing with a power-of-two palette atlas and nearest filtering (or vertex colours), optional corner ambient occlusion and crease-controlled normals, and collision naming for Godot and Unreal. 7Voxel worlds and multiplayer

The same engine has packages for Minecraft-style worlds, separate from the editor: @margoengine/voxel stores 32×32×32 palette chunks with a light byte per cell, a block-type registry and a chunked world with dirty tracking, and adds meshing, lighting, streaming and rendering as separate entries. @margoengine/voxel-net is an authoritative Node server on a hand-written WebSocket, a browser client with prediction and correction, and headless bots for load tests. One server process kept 20 ticks per second with 95% of ticks inside the 50 ms budget for 900 players spread over a map (1,000 went over) and 350 crowded in one spot where everyone sees everyone (400 went over). At that point the server used about one CPU core. Traffic was 13.7 Mbit/s for the 900 spread players, and a block edit reached other players in 31-77 ms median.

docs/voxel-net-capacity-2026-10-21.md · packages/voxel-net/bench/results.json · Ryzen 9 9950X, Windows 11, Node 26.12

Conditions matter here: server and bots ran on one PC over loopback with no latency or loss, the bots do not render, and the prototype has no accounts, persistence or TLS. The multiplayer package is not part of the editor.

9What is not done

  • Release: code signing, a public download, a hosted web version and a licence for the asset pack.
  • Platforms: macOS, Linux, phones and GPUs other than the RTX A6000.
  • Characters: bone-animation authoring and production weight painting.
  • Parity: the open items in section 5, and a calibrated comparison inside the app itself rather than through the engine package.
  • Open engine gaps: deep model hierarchies (65 levels) are refused on GLB export; a face-attach click can miss at an internal grid intersection; a dark oval appears around one showcase model on the studio ground, cause not yet found.
  • Moving code into the engine: the OBJ writer, atlas packing, animation sampling, rigging and palette maths still live in the app and are listed to move into engine packages.

10Reproduce

In the app repository:

npm ci
npm test                    # unit tests
npm run test:browser        # real-Edge browser suite
npm run test:denoiser       # the 72 denoiser gates (dev server running)
npm run test:godot          # Godot imports, headless
npm run test:unity          # Unity Editor imports (after test:unity:prepare)
npm run desktop:build       # the Windows portable

In the engine repository, the MagicaVoxel calibration scripts are in packages/voxel-pathtracer/tests/magicavoxel/, the tracer timings in packages/voxel-pathtracer/tests/browser-check.mjs, and the multiplayer benchmark in packages/voxel-net/bench/.
