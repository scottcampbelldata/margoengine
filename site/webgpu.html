Running without WebGPU

The Margo Engine demos draw with WebGPU. If your browser has no WebGPU, or has it but finds no usable GPU, the demo downloads the WebGL2 compatibility layer instead and runs the same engine code on WebGL2. A note in the lower left corner says "WebGL2 compatibility mode" while it does.

What you download

Only a browser without WebGPU downloads the layer: the demo page checks for WebGPU first and loads the layer with a separate request only when the check fails. A browser with WebGPU downloads none of it, and the demos run exactly as before. The layer is 93,763 bytes gzip with everything rendering needs; the part that runs compute shaders, 42,210 bytes gzip of that, loads only when a demo uses compute. Sizes measured by the engine's size records for this version.

What it looks like

Most demos draw the same pixels as WebGPU on the same GPU: at most a level or two of difference on a pixel, where the two paths compile shaders differently. Some show small differences, for example in particle effects whose random numbers come from functions the layer computes on the CPU, and the page lists every demo with its measured difference: the demos on the WebGL2 layer. The side by side demo draws one scene both ways in your browser and shows the difference and the frame times as you watch.

What it cannot run

  • The voxel path tracer (the voxel sandbox's photo mode): WebGL2's shader compiler takes from 20 seconds to several minutes for each of its kernels.
  • WebXR sessions: WebXR on WebGL2 needs a different kind of layer.

A demo part that needs either shows a message over the scene naming the error code, MargoError unsupported, instead of a blank or frozen view.

Pages with a Content Security Policy

Rendering on the layer needs nothing special. Compute shaders that WebGL2 cannot run on the GPU (atomics, shared workgroup memory, barriers) run on the CPU as JavaScript that the layer compiles at run time with new Function. A page whose Content Security Policy does not allow 'unsafe-eval' gets those kernels refused with MargoError code unsupported; everything else still runs. With WebGPU, nothing in the engine needs 'unsafe-eval'.

Browsers with WebGPU

For the full speed of the demos, update to one of these and reload:

  • Chrome or Edge 113 or newer on Windows, macOS or ChromeOS; Chrome 121 or newer on Android 12 or newer.
  • Safari 26 or newer on macOS, iOS or iPadOS 26.
  • Firefox 141 or newer on Windows.

Still blocked on a current browser? Turn on hardware acceleration in its settings and update the graphics driver: some older GPUs are left out. On Linux, WebGPU may need to be switched on in the browser's flags. A browser with neither WebGPU nor WebGL2 (with float render targets) shows "This demo needs a browser with WebGPU" instead.

In your own app

The same takes four lines. Load the layer only where WebGPU is missing, before creating the engine:

import { Engine } from 'margoengine/core';

const webgpu = 'gpu' in navigator && (await navigator.gpu.requestAdapter()) !== null;
if (!webgpu) await (await import('margoengine/webgl2-compat')).install();
const engine = await Engine.create(document.querySelector('canvas'));
