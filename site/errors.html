Error help

Margo Engine keeps its error messages short and ends each one with a link to its entry on this page, for example Mesh disposed; see https://margoengine.com/errors#disposed. Errors that are not a TypeError or RangeError are a MargoError with a stable code: branch on error.code, not on the message. Optional packages follow the same pattern.

Codes

  • disposed
  • unsupported
  • state
  • failed
  • timeout

disposed: used after dispose()

Engine disposed Mesh disposed Transforms disposed

Cause. The engine, a mesh or the transform store was disposed, and the code kept a reference and called it again. A pick still waiting when the engine is disposed resolves null instead.

Fix. Drop references when you call dispose(), and create a new Engine or mesh (engine.createMesh()) to keep drawing. Check engine.disposed before late callbacks (timers, fetches, promise continuations) touch the engine.

unsupported: the browser or device lacks something needed

Cause. The browser or GPU lacks a capability the call needs. See the WebGPU entry for the messages core throws.

Fix. Feature-test before calling, or offer a fallback path. Branch on error.code === "unsupported".

state: not valid right now

XR button needs a canvas on the page or the parent option Viewer model has no geometry to frame Physics exists on this stage: pass its options on the first call or set them on the world

Cause. The call is valid in general but not at this moment: a re-entrant call from a callback, a missing prerequisite, or a device that is being restored. The re-entrancy, device restore and install entries list the messages.

Fix. Retry later, from outside the callback, or after the prerequisite is in place.

failed: the operation ran and produced no result

BiomeWorld GPU device lost; recreate the WebGPU device

Cause. The GPU or the transform kernel could not complete the work. See the GPU lost and limits entries.

Fix. Read the message for the GPU or kernel detail; most failures are recovered by the engine or need smaller inputs.

timeout: a WebGPU startup step never settled

WebGPU requestAdapter never settled WebGPU requestDevice never settled WebGPU createRenderPipelineAsync never settled Margo: still waiting for <step> after 8 s

Cause. The browser or GPU driver never answered a step of Engine.create: the adapter or device request, or a pipeline compile. Seen on an Intel Arc 140V when 3 or 4 WebGPU pages were alive at once in one browser process: each new page got slower to get a device, and the 4th never did, with no error. The engine warns once after startupWarning ms (default 8000) and rejects after startupTimeout ms (default 30000).

Fix. Start fewer engines at once on one page or in one browser (start the next when the previous one has drawn, or close pages you no longer show). With backend: "auto" and fallback: webglRenderer from @margoengine/webgl2-compat/preview the page draws on WebGL2 instead. Raise startupTimeout for a slow first compile; pass signal to cancel creation yourself. Branch on error.code === "timeout".

Messages

Content Security Policy and WebAssembly

Wasm compilation blocked by CSP; add 'wasm-unsafe-eval' to script-src

Cause. The browser refused to compile Wasm because script-src (or its default-src fallback) does not allow it. Emscripten may wrap the CompileError or EvalError in an abort.

Fix. Serve Content-Security-Policy: script-src 'self' 'wasm-unsafe-eval' on the page and worker responses. Keep the other directives your app needs. This permits Wasm compilation without permitting JavaScript eval. See docs/csp.md in the repository for the packages and worker policy.

@margoengine/creative: texture render targets

Cause. A texture target dimension, mip, layer, format, load operation or clear color is outside its supported range.

Fix. Use cube, array or 3d with positive integer dimensions within device limits and a total allocation at most 256 MiB. Cubes have six square faces. Render one mip and layer at a time. Use rgba8unorm or rgba16float, and finite four-component clear colors. See the creative package README for every default and range.

Moving a canvas to a worker

transferCanvas needs a canvas element in a browser with OffscreenCanvas transferCanvas: expected a Worker transferCanvas: timeout above 0 This canvas has a context or already moved to a worker Worker failed before it took the canvas The worker never called receiveCanvas The page never called transferCanvas receiveCanvas: timeout above 0

Cause. A canvas moves to a worker once, before anything draws on it, and both sides must take part: the page calls transferCanvas and the worker calls receiveCanvas. The call failed because the browser has no OffscreenCanvas, the canvas already has a context or already moved, the worker script failed to load, or one side never arrived within timeout.

Fix. Check workerCanvasSupported() and keep a path on the page. Pass a fresh canvas that no code called getContext on. For a timeout, make sure the worker script runs receiveCanvas() and look for its error in worker.addEventListener("error", ...).

WebGPU required or unavailable

WebGPU required WebGPU unavailable WebGPU adapter unavailable No WebGPU canvas

Cause. engine.pick and engine.rebootDevice need the WebGPU backend; on the WebGL2 fallback they reject unless the app adds webglPicking and webglRestore. Engine.create found no navigator.gpu, no adapter, or a canvas that already has another context.

Fix. Use a browser with WebGPU (current Chrome, Edge or Safari; margoengine.com/webgpu), turn on hardware acceleration, or pass {backend: "auto", fallback: webglRenderer} from @margoengine/webgl2-compat/preview. Give the engine a fresh canvas that has no 2D or WebGL context.

Geometry unavailable during device restore

Geometry unavailable

Cause. The GPU device was lost and the engine is recreating it; GPU resources cannot be read or created until it finishes.

Fix. Wait for engine.rebootDevice() (or the next frame) to finish, then retry. Packages restore their GPU state in onDeviceRestored.

GPU lost or a GPU validation error

GPU lost: <reason> <WebGPU validation message>

Cause. The browser lost the GPU device (driver reset, tab in the background too long, GPU process crash), or WebGPU reported an uncaptured validation error.

Fix. Core recreates the device itself; recreate textures your code owns (view targets) in onDeviceRestored. A validation error names the GPU object at fault: fix the call that created it.

Render or frame graph re-entered

Render recursion Graph executing Graph recursion

Cause. engine.render was called from inside a frame callback, a plugin hook or a pass, or a pass added passes to the graph or ran the graph while it was executing.

Fix. Call render from your own loop or engine.start(), never from inside a frame. Add or remove passes from registerPasses, setup or outside the frame.

Optional package missing or format unknown

Install <package> Specify format

Cause. stage.load needs an optional package for this format and it is not installed, or the URL has no known extension.

Fix. Install the named package (for example npm i @margoengine/gltf), or pass {format}: one of gltf, glb.

Camera and controls values

Invalid projection Camera at target Vertical camera Invalid frustum Invalid fit Bounds exceed far: raise camera.far Invalid pivot Invalid orbit Invalid pan Invalid projection view offset Invalid projection tiles Invalid projection lens Invalid off-axis screen Invalid off-axis eye Invalid oblique plane Invalid physical camera Invalid wide angle mode Invalid wide angle distance Invalid wide angle view

Cause. The camera cannot build a view: fov outside 0-180, near not above 0 or far not above near, the position equal to the target, a view parallel to camera.up, or non-finite values. fitToBoundingBox needs min <= max, aspect > 0, duration >= 0 and padding >= 1, and a box that fits inside far. Controls need finite input and a camera off its target. @margoengine/cameras also refuses a view offset or tile size that is not above 0, a focal length, film gauge or aspect that is not above 0, an off-axis screen with collinear corners or an eye behind it, an oblique plane the camera is not behind, and a physical camera with an aperture, shutter, ISO, focal length, focus distance or frame rate that is not above 0.

Fix. Keep 0 < fov < 180 and 0 < near < far; move the position off the target; for straight-down views set camera.up (for example [0, 0, -1]) or use CameraProjection from @margoengine/cameras. Raise camera.far for large models. For cameras options, pass whole sizes above 0, put the eye in front of the screen, and keep the camera on the clipped side of an oblique plane.

Transform values

Retained vector: use a transform setter Invalid transform Scale nonzero Quaternion nonzero Invalid poses Invalid transform: <k> Quaternion nonzero: <k> <name>: <n> values <name>: finite values Invalid transform/bounds: <id>

Cause. A position, rotation, scale, quaternion or other vector had the wrong length, a value that is not a finite float32, a zero scale, or an all-zero quaternion. engine.writePoses names the failing row k, refuses a count above ids.length or poses shorter than count * 7, and writes nothing when any row fails. The kernel names the entity whose transform or bounds went non-finite.

Fix. Retained mesh position, rotation and scale refs cannot be replaced: use .set(x, y, z), .setAll(value) or mesh.setPosition, setRotation and setScale. Pass arrays of the stated length with finite numbers; use nonzero scale factors and a nonzero quaternion. Give writePoses 7 numbers a mesh. Look for divisions by zero or NaN upstream of the entity id the kernel reports.

Parents and meshes from another engine or scene

Foreign parent Hierarchy cycle Parent depth: 64 Foreign mesh

Cause. A parent belongs to another engine or scene, would make the mesh its own ancestor, or nests deeper than 64 levels; or the stage was given a mesh of another engine.

Fix. Parent meshes of the same engine and scene, pick a parent outside the mesh subtree, and keep hierarchies under 64 levels. Create meshes with the scene they belong to (scene.createMesh()).

Scenes

Unknown scene: use engine.createScene() Default scene: dispose the engine instead

Cause. A scene from another engine, or one already disposed, was passed in; or engine.scene (the default scene) was disposed.

Fix. Use scenes from this engine: engine.createScene(). The default scene lives as long as the engine: call engine.dispose().

Geometry

Invalid geometry Box size: positive Sphere radius Sphere segments: 3..256 No geometry

Cause. Core geometry accepts three empty arrays, or needs 3 to 1,000,000 vertices, a triangle index count that is a multiple of 3, indices inside the vertex range, and finite positions and normals. Boxes and spheres need positive sizes and 3-256 segments. Fitting needs at least one mesh with geometry.

Fix. Split meshes over 1,000,000 vertices, check index ranges, and pass positive sizes. Give the model meshes with geometry before fitting.

Material values

Invalid material Invalid Color

Cause. A material colour, roughness or metalness was outside 0..1 or not finite, doubleSided was not a boolean, a colour was not #rrggbb or linear [r, g, b], or the material data was changed directly to an invalid value.

Fix. Pass #rrggbb or linear [r, g, b] in 0..1, roughness and metalness in 0..1, a boolean doubleSided, and change values with material.set().

Lighting values

Invalid lighting

Cause. The light direction was zero, or an intensity, radiance or ambient value was negative.

Fix. Use a nonzero light direction and non-negative intensities.

Views, rectangles and picking

Invalid views Invalid view: pass {camera, viewport} Invalid view target: use 1-sample colour Invalid view depth: use the scene depth format and samples, or omit depth Partial-view clear: draw extra attachments with clear: false Invalid draw rectangle Draw rectangle exceeds target Invalid pick

Cause. render({views}) needs a non-empty array of {camera, viewport}. A view target needs 1-sample colour and, if it has a depth, a depth of the same size in the scene depth format and sample count (core draws into it directly and does not convert another format). A pass drawing a partial rectangle with extra colour attachments cannot clear them. Draw rectangles are 4 integers inside the target. pick needs finite CSS pixel coordinates.

Fix. Pass {camera, viewport} objects; use 1-sample target colour; give a target depth the scene depth format (depth32float-stencil8 when the device has it, else depth32float) and sample count (4 with 4x MSAA, else 1), or omit it (a package can resolve the core depth itself with a SceneTarget); draw extra attachments with clear: false; keep rectangles inside the target; pass finite numbers to pick.

Cause. A @margoengine/headless call got something it cannot use: no WebGPU binding, a size that is not a whole number, an engine on a page canvas or the WebGL2 backend, a read before the first frame, or an HDR format. For video: an empty or mixed-size sequence, a codec its container cannot hold, a runtime without WebCodecs (Node has none), an odd size for H.264, or an ffmpeg that is missing or exited with an error. For comparison: images of two sizes, limits out of range, or a PNG that is interlaced or damaged. For output formats: a JPEG quality outside 1 to 100, an image over the size the format allows, lossy WebP in a runtime with no WebP encoder, an EXR without the environment package, or a texture that is not a float format. Two headless stages alive at once on different gpu objects would fight over the same globals.

Fix. Pass installGPU the gpu from your binding, give createHeadlessCanvas whole sizes from 1, create the engine on that canvas with backend: 'webgpu', and call engine.render() before readPixels or toPNG. HDR output cannot be read this way; leave the canvas format at its default. For video, keep every frame one size, use even sizes for H.264, call encodeVideo in a browser or worker or pass webCodecs, use encodeWithFFmpeg in Node, and read the end of ffmpeg's log in the error's cause. Give headless stages alive at once the same gpu. Compare images of one size, and save an interlaced reference PNG again without interlacing. For formats, use quality in range, encodeWebP without quality for lossless output in Node, install @margoengine/environment for EXR, and read rgba16float or rgba32float textures only.

Pixel camera and layer options

Invalid pixel camera width Invalid pixel camera height Invalid pixel camera minZoom Invalid pixel camera maxZoom Invalid pixel camera zoom Invalid pixel camera position Invalid unitsPerPixel Invalid parallax Invalid fit size Invalid pixel order Invalid pixel layer Invalid pixel layer size Invalid pixel layer anchor Invalid pixel image LayerCompositor needs a camera

Cause. A PixelCamera, LayerCompositor or PixelLayer value is out of range. Sizes and zoom must be whole numbers, because a fractional scale would blur pixel art. Layer fields are read each frame, so a bad one throws from the frame that first reads it.

Fix. Give the camera whole width, height and zoom (zoom from minZoom to maxZoom) and a finite position. Keep a layer's opacity from 0 to 1, its x, y, z, rotation, parallax and pivot finite, blend one of normal, add, multiply or screen, anchor view or world, and pass write bytes of exactly width * height * 4 that fit the target.

Pixel layer state

Pixel layer texture needs an attached compositor

Cause. A layer's texture or target was read before its LayerCompositor was attached to an engine, so there is no device to make the texture on.

Fix. Use LayerCompositor.attach(engine, options), or engine.use(compositor), before reading layer.texture. layer.write works earlier: the picture waits until the target exists.

Pixel-exact backbuffer size

Invalid exactSize

Cause. exactSize was an array that is not two whole numbers from 1 to 8192.

Fix. Pass exactSize: [width, height] in backbuffer pixels (for example [320, 180]), or true to keep the canvas width and height attributes. Zoom with CSS: set the canvas size to a whole multiple and image-rendering: pixelated.

Sprite options and sprite fields

Invalid sprite Invalid sprite rect Invalid sprite tint Invalid sprite camera Invalid sprite capacity Invalid sprite order Invalid sprite clear Invalid sprite pixels SpriteLayer needs an atlas Sprite normal atlas differs in size Too many sprites in a layer Invalid sprite animation Unknown sprite clip

Cause. A SpriteLayer option or a Sprite field is out of range. Sprite fields are read each frame, so a bad value throws from the frame that first reads it: a non-finite position, an alpha outside 0 to 1, or a rect that is not whole texels inside the atlas.

Fix. Keep x, y, z, scale, pivot and rotation finite, alpha from 0 to 1, and rect as [x, y, width, height] in whole texels inside the atlas. camera.zoom must be above 0, tint is 0xrrggbb, #rrggbb or #rgb, atlas bytes are width * height * 4 long, and a normal atlas is the size of the colour atlas. For too many sprites, split them across layers. Animation clips need at least one frame of whole-texel rectangles, positive durations and fps, an event frame inside the clip, a speed and dt of 0 or more, and play takes a clip name you passed in clips.

2D lighting

Lighting2D needs a target Invalid light value Unknown occluder shape Invalid occluder value Lighting2D normals differ in size from the target

Cause. A Light2D field, an occluder or a Lighting2D option is out of range, or the normals texture is not the size of the target.

Fix. Keep light positions and angles finite, intensity, height and softness 0 or more (softness up to 1), radius, falloff and cone above 0, color and ambient as #rrggbb, and camera.zoom above 0. Occluders are polygon, polyline, segment, box or circle shapes with finite numbers. Make normals the size of target.

Palette pass

A palette holds 1 to 256 colours Invalid palette colour Invalid palette value A palette swap has as many colours as its palette PaletteQuantize needs a palette, a source and a target Palette source and target must differ

Cause. A PaletteQuantize option or a palette helper argument is out of range, or the pass was asked to read and write one texture, which WebGPU forbids.

Fix. Pass 1 to 256 colours as #rrggbb or [r, g, b] bytes, a swap of the same length, a known dither and distance, a spread of 0 or more, and two different textures: draw into one pixel layer and show another.

Tile map renderer options

TileMap needs a map TileMap needs atlases Tileset has no atlas Tileset larger than its atlas Invalid tile map order Invalid tile map clear Invalid tile map camera Invalid tile atlas pixels Unknown tile layer Tile outside the layer Tile layer too large for the device

Cause. A TileMap option does not fit its map: a tileset that drawn tiles use has no entry in atlases, its columns, tileCount, margin and spacing reach past the atlas image, a mapLayers or setTile name is not a tile layer of the map, a cell is outside its layer, or camera.zoom is not above 0.

Fix. Pass atlases keyed by tileset name, with images at least as large as the tileset says. Use tile layer names and whole cells inside the layer. Split a layer too large for the device limit maxStorageBufferBindingSize into several.

Tile map renderer state

Image collection tilesets are not drawn Tile atlas lost with the device; call setAtlas

Cause. Drawn tiles belong to a tileset with columns: 0 (one image per tile), which the renderer cannot cut from one atlas, or a map built on a plain GPUTexture atlas drew after a device loss (the texture died with the old device).

Fix. Pack an image collection into one atlas image and set its columns. After a device loss call setAtlas(name, atlas), or pass the atlas as pixels or a function so the map makes it again.

Low-res 3D view

Render3D needs a camera Invalid Render3D size Invalid Render3D value Render3D needs attaching before its view is read Render3D target differs in size A Render3D camera matrix needs an inverse

Cause. A Render3D or renderSpriteFrames option is out of range, its view was read before the plugin was attached, or the target is not the size of the view.

Fix. Attach with Render3D.attach(engine, options) first. Pass whole width and height, a target of that size, an outline color as #rrggbb, and at least one angle.

Sprite layer state

Sprite already in a layer Sprite atlas lost with the device; call setAtlas Sprite normals need one sample and a same-size target

Cause. A sprite was added to a second layer, a layer built on a plain GPUTexture atlas drew after a device loss (the texture died with the old device), or a normal target does not match the colour target.

Fix. Call remove before adding a sprite to another layer. Call setAtlas after a device loss, or pass bytes, an ImageBitmap or (device) => GPUTexture, which come back by themselves. For normals, draw at one sample per pixel (exactSize on the engine, or your own target) with a single-sample normal target of the same size.

Capacity and GPU limits

Capacity: 1..8388608 Capacity Transform allocation GPU buffer limit Shader limit: 64

Cause. The transform store capacity is outside 1..8,388,608, a grow did not raise it, the kernel could not allocate memory, a buffer is larger than the device allows, or more than 64 shader variants were requested.

Fix. Lower capacity, split large geometry, and reuse materials and plugins so fewer shader variants are built.

Wrong argument types

Expected canvas Unknown backend Invalid camera Invalid geometry Invalid material Invalid plugin Invalid pass Invalid delta receiveShadow: boolean Visibility: boolean Box: 3 values fit: boolean Invalid stage options Expected element shadows: contact, cascaded or false Turntable: finite seconds not 0, finite resumeAfter 0 or more

Cause. An argument had the wrong type: not a canvas or element, an unknown backend, a camera, geometry or material not from core, a plugin without a unique name and setup, a pass without a unique name, finite order and execute, a frame delta outside 0..1 seconds, or a non-boolean flag.

Fix. Pass core objects (Camera, Geometry, PbrMaterial), a backend of "auto", "webgpu" or "webgl2", plugins and passes with unique names, and booleans for flags.

compatibility-layer: the WebGL2 compatibility layer cannot do this (@margoengine/webgl2-compat)

Cause. A MargoError with code unsupported from the WebGL2 compatibility layer: a shader or a call needs something the layer does not map onto WebGL2, and the message names it: something WebGL2 cannot do at all (subgroups, cube array textures, vertex strides above 255 bytes, render shaders that write storage buffers or textures), or something the CPU tier of compute cannot run (multisampled or external textures, or a cube texture in a built-in other than textureSampleLevel, textureDimensions and textureNumLevels, read by a kernel with atomics, workgroup memory or barriers; a page whose Content-Security-Policy forbids JavaScript compiled at run time). install() throws the same code when the browser has no WebGL2 at the full tier, naming what is missing. The margoengine.com demos, which load the layer only when WebGPU is missing, show such a refusal over the scene with its code instead of a blank view (docs/webgl2-compat-demos.md). For the work budget, make the dispatch smaller or raise cpuWorkBudget in install() or on the device. Report any other failed error with the shader that caused it.
