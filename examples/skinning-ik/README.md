# The light keeper

A local Margo Engine counterpart to the [Three.js skinning / IK study](https://threejs.org/examples/#webgl_animation_skinning_ik): a smoothly skinned robot carries a reflective orb in an original Blender workshop. Moving the requested target bends the arm while the orb stays in its palm. All rendering, deformation, controls, and reflection capture use Margo packages.

## Run

From the repository root, with Node 22.12 or newer:

```sh
npm ci
npm run build:packages
npm run dev:ik
```

Open `http://127.0.0.1:5191/examples/skinning-ik.html` in a WebGPU browser. Drag the orb to request a new arm position; enable **Show arm rig** for the target's axis handles and reach-limit guide. The orb always remains attached to the wrist-local palm grip, including when IK is disabled, a pose is held, or a request exceeds the arm's reachable distance. Sliders, presets, and the keyboard orb control move the independent desired target. With automatic solving off, **Solve one step** updates the held arm pose. Drag elsewhere to orbit, pinch/scroll to zoom, Escape to release a drag, and **Reset the workshop** to restore the scene and view.

The arm retains movement in front, behind, and overhead, with natural reach clamping. The optional `@margoengine/kinematics-constraints` package projects the requested orb center out of an inner torso capsule before the rig adapter solves the arm. This small proxy sits inside the authored torso; it is not a replacement for its full surface. A tight convex torso collider checks the posed upper-arm and forearm surface hulls, hand, and orb; the adapter tries alternative elbow directions before limiting a request that would enter the torso. The shoulder's intentionally mounted bearing is exempt. The lamp stays static at its authored pose.

The sliders each select a complete motion path, with the authored Home at 50%. **Near & far** folds the elbow, lowers the hand beside the body, then extends it in front. **Height** moves from the side to overhead. **Side to side** sweeps across the front of the body, aided by a smooth upper-body turn. Other slider readouts show the nearest position on their respective paths; they are not independent Cartesian offsets. Slider changes follow intervening path waypoints; changing tracks returns through Home before joining the new track. Waypoints advance only when the accepted orb reaches them, preventing the target filter from cutting through the torso or head between otherwise valid endpoints. Home and High presets use the same routes. Free dragging, other presets, and keyboard control still request arbitrary positions. A critically damped target filter bounds command speed to 1.8 metres/second before collision solving, so sudden slider reversals advance through checked poses. It does not interpolate already accepted joints. The torso turn is bounded to 0.85 radians, advances at most 1.6 radians/second, and preserves bone lengths and shoulder attachment. Its collision frame follows the Body bone before target projection or clearance evaluation. Manual holds and reflection renders reapply the presented turn without advancing it.

Eye tracking aims the head's central optical ray from the actual lens center, rather than from the neck pivot. Absolute rest-relative rotations avoid accumulating extra movement during reflection captures. Neck travel is bounded to 1.3 radians; targets outside that travel or too close to the optical assembly report a limited aim in the diagnostic metrics. The two lenses remain parallel, as authored. Candidate acceptance also checks the active armor, hand and orb against the posed head hull. A separate head-only arm envelope includes the mounted shoulder parts and blended skin that are intentionally excluded from torso contact. Proposed head rotations check that envelope before changing the scene. Head aiming also checks the orb envelope and the actual lower cowling against the chest-top plane. The final diagnostic pass reads the accepted pose without changing it after clearance validation.

`BodyIK.solve(desiredOrb, dt)` converts the requested orb center into model-local coordinates, calls the package's `AvoidanceSolver.resolveTarget`, and passes the projected target through the existing contact slide. The adapter subtracts the grip offset to obtain the wrist target, solves the analytical two-bone chain, restores the wrist's tool orientation, and checks the actual mesh hulls before accepting a candidate. Target projection uses the real positive frame delta; reflection renders reuse the accepted pose. Reset also clears projection history. Damping remains in the existing contact-recovery logic. This integration uses the package's target-only API: reach conditioning, elbow selection, and contact recovery remain owned by the robot adapter. It does not claim the full library `solve()` swivel-rate contract or continuous collision detection.

```sh
npm run build:ik
node --test tests/skinning-ik*.test.js
node scripts/test-skinning-ik-constraints-browser.js
node scripts/test-skinning-ik-motion-browser.js
node scripts/profile-skinning-ik.js --label=local --phases=default,torso-pointer-drag
node --test packages/stats/test/stats.test.js packages/shadows/test/bounds.test.js packages/post/test/ssao.test.js
npx vite preview --outDir test-results/skinning-ik-site --host 127.0.0.1 --port 5192 --strictPort
```

The standalone build opens at `http://127.0.0.1:5192/`. Its only output is `test-results/skinning-ik-site/`; it does not rebuild or deploy the production site. `build-report.json` lists bundled modules, package names, JavaScript sizes, and GLB hashes. The build rejects Three.js and other third-party runtime dependencies and verifies the optional animation, animator, and kinematics-constraints packages are present. The unused stage CAD loader is excluded from this demo build.

The focused tests cover world-space IK and grip attachment, broad reach and torso clearance against actual exported vertices, asset validity and provenance, timestamped GPU audit behavior, Stats sampling, single-layer shadow bounds across camera/light changes, and SSAO integration.

The allocation profiler records natural GC, sampled allocation stacks, real animation-frame and reflection counts, and both JavaScript heap and backing-storage sizes. Use `--duration-ms=60000 --warmup-ms=15000 --gc-only` for a longer run without allocation sampling. Add `--scene-url=http://127.0.0.1:5192/` after building to measure the actual minified standalone preview; the script verifies its build report and bundle hashes. The report retains source hashes and browser/GPU identity and rejects source changes during capture. Sampling and tracing add overhead, and the profiling harness has its own allocation stacks. A falling heap graph is not evidence of a retained-memory leak. Reflection snapshots reuse private storage until the public `texels` getter exposes an array; subsequent bakes preserve that published array's identity and contents.

The synchronous zero-delta renders inside a reflection bake can reuse the already validated presented pose. `probe-pose-reuse.ts` checks the transforms, hierarchy, matrices, limits, morphs, controls, animation inputs, and update-hook ordering at both animation and pose boundaries. Changed or unsupported inputs take the ordinary update path. The `probePose` metrics count attempted, reused, and fallback capture poses; ordinary frames still solve normally. GPU skinning retains validation and compute dispatch on every render while avoiding identical bone and morph buffer uploads. These changes reduce repeated work; they do not guarantee zero browser allocations or garbage collections.

## Edit and reproduce

- `../skinning-ik.html` and `workshop.css` define the page and controls; `main.ts` composes the scene. The approved visual reference is preserved at `../assets/source/skinning_ik/visual-target.png`. It was generated with the built-in imagegen tool; its exact prompt is retained in `../assets/source/skinning_ik/visual-target-prompt.txt`.
- `rig-ik.ts` adapts the optional animator's analytical two-bone solver to world-space shoulder, elbow, and wrist rotations. It preserves local bone translations and validates positive uniform ancestor scales.
- `arm-controls.ts` maps normalized controls onto model-local orb paths; `arm-control-route.ts` follows their waypoints across interrupted and cross-track requests. `torso-aim.ts` applies bounded upper-body yaw and transports the original collision coordinate frame with the skinned torso. `head-aim.ts` solves the offset optical ray and reports the presented aiming error.
- `body-ik.ts` uses the authored tapered torso rings and rear panel as a convex collider. `body-ik-shapes.ts` contains four separate upper-arm component hulls (bellows, piston barrel, armor, copper shaft) and a 94-point forearm hull, including the thin bearing washers. Only the authored shoulder cap, bearing, washer, axle, and hub union is exempt; the proximal shaft remains collidable. The solver tests nearby elbow directions and slides the held hand along torso contact rather than pinning lateral input to the previous pose. Contact release follows checked intermediate poses; free movement follows the filtered target command. Reflection renders reuse the saved pose instead of advancing that recovery. `../assets/source/skinning_ik/extract_ik_shapes.py` refreshes the hulls through Blender MCP after arm geometry changes.
- `performance-hud.ts` combines optional `@margoengine/stats` counters, measured GPU pass timing, frame-time history, and the browser's JavaScript heap reading. A compact pill at the viewport's top right expands the panel. Heap values are sampled every 500 ms with a rolling 60-second range; unsupported readings are labeled unavailable. GPU timestamp queries are requested when the adapter supports them. Manual reflection capture renders are excluded from FPS sampling. In the standalone build, three footprint rows show measured **Core + stage** gzip bytes, **Demo JS · all chunks** gzip bytes, and **Scene assets** bytes from `build-report.json`. The tooltip records the build time, chunk/module/import counts, and raw JavaScript size. These are build measurements; heap readings describe JavaScript allocations and are separate from asset bytes or GPU memory.
- `gpu-audit.ts` records timestamped GPU samples, preceding UI actions, viewport changes, and current host-side context in the viewport's `data-gpu-audit` attribute. It reports temporal correlation without assigning a cause. `encodedAt` is the CPU encoder-finish time and `readAt` is CPU readback completion, both relative to `performance.timeOrigin`; neither gives GPU execution host time. Pass times cover the Stats-tracked main encoder; separate probe capture/prefilter encoders are excluded. Pass indices have no inferred labels, and counters/context observed later are not attributed to that sampled encoder.
- `Animation` supplies the existing GPU skinning pass. The demo's `WorkshopAnimator` owns the sampled base pose; the IK plugin follows it before the final world-matrix update. Head tracking and the wrist orientation correction follow the arm solve. Core and stage receive no new features.
- A geometry-free target handle owns requested positions. Direct dragging records the requested location and immediately restores the visible orb to its palm grip. After each sampled/solved pose, the full wrist world matrix places the orb, so local orientation and model scale follow correctly. Unreachable targets clamp the arm; they never detach the orb.
- The optional `@margoengine/environment/probes` package supplies `LightProbes` at resolution 128. The demo follows the held orb's world position with `setReflectionPosition(0, orbPosition)` and rebakes the workshop while excluding the orb itself. `bake({samples: 256})` bounds rough-level GGX filtering while preserving the sharp base level; pipelines are cached across captures. Live captures continue during dragging, gizmo use, slider/keyboard input, idle head animation, and moving-light animation. The active cadence adapts to `max(50 ms, last full bake duration × 4)`; quiet captures are spaced at least 250 ms apart. Drag releases and control changes queue a final capture after any in-flight work, respecting a 50 ms minimum interval, so continuous interaction cannot indefinitely starve reflection updates. The viewport's `data-reflection` metrics expose resolution, cadence, capture position, and timings. The live reflections control enables that refresh. The locally stored Artist Workshop HDR supplies the environment and reflection fallback. Shutdown waits for any current GPU probe bake.
- The optional `@margoengine/shadows` package uses a single 2048² PCSS shadow-map layer fitted to a fixed scene volume, with outer bounds `min: [-1.5, -0.27, -1.48]`, `max: [1.5, 1.82, 1.53]`, `casterMargin: 1`, `lightSize: 0.012`, `normalBias: 0.0004`, and `bias: 0.00003`. `shadow-bounds.ts` supplies 388 support points from the actual workshop geometry plus a rounded arm/orb reach envelope centered at `[-0.24, 1.03, 0]` with radius `0.78`. The Blender extractor `../assets/source/skinning_ik/extract_shadow_bounds.py` conservatively expands the hull so every facet contains the full analytic reach sphere and original geometry; its point cloud remains inside the outer bounds. This avoids fitting the light to empty box corners. Camera orbit and zoom do not expand that fitted volume. The optional PostStack runs SSAO (`samples: 32`, `radius: 0.1`, `bias: 0.0015`), then Bloom (`strength: 0.12`, `threshold: 1.3`), then Neutral tone mapping (`exposure: 0.25`). `TransparentCanvas` leaves the DOM's `#F4EFEB` cream visible behind the scene. A broad fill of that cream color, converted to linear RGB and scaled by `0.16`, is added to the decoded HDR before environment processing (`intensity: 1.0`). It lifts diffuse shadow fill and reflection captures together while preserving the original HDR download and bright window detail.
- Append `?shadowDebug=1` to the demo URL for a one-shot readback of the actual GPU directional depth map after its first render. The diagnostic displays the depth map, occupied bounds, and coverage, and records the fitted matrix in its `data-shadow-debug` metrics. It uses the real shadow texture rather than a substitute scene render, is disabled by default, and releases its temporary readback buffer.
- Editable asset: `../assets/source/skinning-ik.blend`. Generator: `../assets/source/skinning_ik/build_robot.py`. The generated `../assets/skinning-ik.glb` includes the rig, smooth skin weights, idle clip, and workshop; `../assets/skinning-ik-orb.glb` contains the separately loaded mirror geometry that remains attached to the palm.
- `../assets/source/skinning_ik/surface_textures.py` builds the material image nodes and metric UVs before export. It loads the Poly Haven maps described below for wood and stone, packs them into the Blender file, and generates deterministic 512² paint, metal, rubber, ceramic, and fabric maps for the other surfaces. Base color uses sRGB; roughness and OpenGL normals use Non-Color. Wood repeats at approximately 0.55 m, stone/concrete at 3 m, and the other generated surfaces at 0.4 m. GLB export embeds the used images; the browser does not download textures from Poly Haven.

The platform uses a dry, dielectric limestone material: metalness is explicitly zero, scan roughness is remapped with `0.80 + 0.15 × source`, and the OpenGL normal strength is `0.25`. Its albedo is graded around `#C9BDA9` with restrained aggregate variation. The exported 8-bit roughness spans approximately `0.855–0.937` (mean `0.881`), avoiding the original scan's medium roughness and broad sheen. Source map files remain unchanged. Soft moving light shadows and SSAO still darken occluded areas; those are separate from the surface's roughness.

The stone top is at `Y=0`. Both beveled rubber soles span `Y=-0.001` to `Y=0.009`, embedding one millimetre into the stone and meeting the porcelain toe underside. These are the robot's actual outsoles. The editable Blender scene and exported GLB share those contact heights.

The instrument case under the workbench carries the exact two-line dedication **Margo Engine ♡ / Made for Margie** on its lower rear panel, below the cross braces. It is baked onto the existing rear polygons; it adds no lettering geometry. The native source and material generator preserve it.

Use the running Blender MCP connection for asset work. Save the current Blender file before executing the generator. Set its `PROJECT_ROOT` global to this checkout and execute the script with `__name__ = '__main__'` and `__file__` set to its absolute path. It recreates the separate Light Keeper scene, runs the surface pipeline, exports both GLBs, saves the editable `.blend`, and writes a render and build evidence under `test-results/ik/`. Keep the source map folder present to reproduce the photographic wood and concrete; the pipeline uses procedural fallback maps if those source files are absent. Reload the browser after exporting; rerun `build:ik` for a fresh standalone bundle.

Raw Poly Haven downloads and their provenance JSON files are retained in `../assets/source/skinning_ik/textures/polyhaven/`. The source `.gitignore` excludes regenerable procedural maps while keeping those upstream files. Asset tests check the actual exported GLBs, blended skin weights, embedded PBR images, arm hierarchy, provenance, and native source availability; Khronos validation must report zero errors and warnings.

## Texture provenance

The workshop uses [Wood Table Worn](https://polyhaven.com/a/wood_table_worn) and [Concrete Floor Worn 001](https://polyhaven.com/a/concrete_floor_worn_001) from [Poly Haven](https://polyhaven.com), both photographed by Dimitrios Savva and processed by Rico Cilliers. The diffuse, OpenGL normal, and roughness source maps are 1024² JPGs under [CC0-1.0](https://polyhaven.com/license). The [source manifest](../assets/source/skinning_ik/textures/polyhaven/manifest.json) records exact download URLs, authors, hashes, dimensions, and map color spaces. `black_walnut_veneer_02`, by Jenelle van Heerden, is available in that source folder as an unused CC0 alternative; it is not assigned or embedded by the current pipeline.

The environment is [Artist Workshop](https://polyhaven.com/a/artist_workshop), by Oliksiy Yakovlyev, also from Poly Haven under CC0-1.0. The runtime loads the local `../assets/skinning-ik-workshop.hdr`; [environment.json](../assets/source/skinning_ik/textures/polyhaven/environment.json) records its source URL, verified hashes, author, and decoded 1024 × 512 dimensions. All runtime assets are local; there is no live Poly Haven dependency.

The robot, rig, animation, geometry, asset generation code, and other procedural surfaces are original Margo Engine assets, copyright 2026 Scott Campbell, under the repository's MIT license. No reference character or third-party model is included. See [asset ownership and provenance](../assets/skinning-ik-LICENSE.md). The completed Tokyo assets and source are separate and preserved.
